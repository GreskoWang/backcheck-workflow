# 完整执行流程

1. **确认范围。** 对象、时间窗、交付位置和可验收条件从当前请求取得。团队派单先核对 requestId/哈希和 `verified_dispatch_scope.assignments`，只执行本机指定代号。每个新 requestId 建新线程，同 requestId 的恢复复用原线程。不要从历史 metrics 或 fixture 启动任务。
2. **建立断点。** 一份当前结论记录事实、已读来源与剩余范围。平台持久 owner 保存自身页面和 capability，其他会话不接管它。页面消失记录实际原因或未知，恢复次数随断点保留。
3. **调查。** 主页从新到旧，正文、引用归因、图片与重点视频按实际范围阅读；十四平台固定合同和画像补查保留。先验证少量真实页面的批量映射和正文完整性，再按组采集。采集与人工实际阅读分别记账。
4. **减少重复。** 稳定来源 ID 去重；窗口重叠不重复计费。正文短摘要标记截断，完整正文单独读。清楚图片批看，有疑点才放大；拼图等比例完整保留来源与图号。预算不足就保存 remaining，不把不足写成完成。
5. **处理故障。** 等待加载用同页、只读、有界轮询。真正超时、隔离或状态未知立即保留断点，按既定恢复额度处理，不能换页或换代理重置额度。连接、单页面、网站响应、内容未加载分别判断。每 30 分钟或 50 次往返无阶段结果，改变粒度或策略，不继续重复调用。
6. **写作和交付。** 已确认事实按“一句事实 → 必要截图 → 原帖完整 URL”写入对应平台，本人、转发、引用和第三方分别归因。无风险模块按 `platform-format.md` 固定措辞；证据不足不得套用无问题。原生复制正式模板，保护用户手工改动，阶段结论合并写独立工作稿，完整后才交付指定成品。
7. **审阅。** 稳定 revision 后全文机器检查和语义审阅，必要时看实显。真实修改触发全量机器检查、差量语义和必要视觉检查。当前 token/revision 的 PASS 才支持交付；个人 PASS 不能代替团队最新稿 PASS。

已有方法的权威文件：三项背调技能的 SKILL.md 与 references。业务风险、平台模块、顶部风险对应、H3/H4、Callout、截图归属、链接位置、连续编号等合同保留。工具内部过程记录不混入最终成品。
