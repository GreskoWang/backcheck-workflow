# 飞书 API 操作

## 唯一写入通道

飞书正文的创建、修改、删除、排版、链接、图片和回读全部使用飞书 OpenAPI／MCP。不得用电脑操纵、鼠标键盘或浏览器界面编辑正文。涉及正文和格式时，浏览器仅作只读查看；身份续权按主 Skill 的原账号、既有权限 OAuth 规则执行。

在线模板 token 从本机配置的 `template_document_token` 读取，永久只读。原生copy请求中的file_token是只读来源，允许使用模板token；其余修改、删除、移动、权限变更和正文写入的目标均不得是模板。后续填充只使用copy返回的新文档token。

优先使用当前环境实际提供的等价接口；常用能力包括：

- `docx_v1_document_get`、`docx_v1_document_rawContent`：核对文档、标题和正文；
- `docx_v1_documentBlock_list`、`docx_v1_documentBlock_get`：读取结构、样式和真实 block id；
- Drive `POST /drive/v1/files/{file_token}/copy`：原生复制模板，创建目标文档；MCP未暴露copy时，通过既有授权的OpenAPI调用，不因此退回空文档重建；
- `docx_v1_documentBlock_patch`、`docx_v1_documentBlock_batchUpdate`：修改文字、样式、链接、网格和图片；
- `docx_v1_documentBlockChildren_create`：新建标题、正文、Callout、网格、列、列表和图片块；
- `docx_v1_documentBlockChildren_batchDelete`：删除已明确定位的占位块或旧章节。

使用用户授权时设置 `useUAT: true`。不得读取、导出、重放或保存浏览器 Cookie、token、密码、验证码或其他凭证。

## 创建或续写

1. 先通过 API 读取在线模板；同一目标文档只完整读取一次。模板的 block tree、类型、父子顺序、列宽、图标、颜色和空白块以[版式与文风](feishu-style-guide.md)解释，平台正文以[十四平台成品格式](platform-format.md)解释。
2. 当前任务或 `调查结论.md` 已有目标飞书 URL 时，读取该文档当前内容并续写。没有目标文档时，按下节原生复制模板，副本标题为`M.D-对象名`。复制后核对完整样式，再局部替换正文与占位，不逐块重建Callout或网格。若模板标题层级、示例数量或平台文案与已验收的单人格式不同，按对应合同在副本中调整，保留可直接复用的卡片容器。
3. 新文档不能复用模板或其他文档的 block id。创建后先核对标题和 token，再写正文。
4. 用户已手工修改目标文档时，先回读。把其事实、截图、完整 URL、链接、格式和范围外内容视为受保护内容；只改当前授权范围。
5. 同一目标文档只有一个写者。研究可并行，目标文档的创建、修改、上传和回读按修订顺序串行。

### 原生复制模板

1. 读取来源模板及当前任务已有目标，确认需要新建；先保存一次创建意图，避免响应不明时重复建文档。
2. 目标文件夹使用用户指定的目录；未指定时，可用既有用户授权请求`GET /drive/explorer/v2/root_folder/meta`取得根目录token。
3. 请求`POST /drive/v1/files/{源模板token}/copy`，body为`{"name":"M.D-对象名","type":"docx","folder_token":"目标目录token"}`。记录返回的`data.file.token`和`data.file.url`，确认新token与来源不同。只使用已有OpenAPI授权，不读取浏览器凭证。
4. 分页读取副本所有区块，沿父子顺序与来源对应，排除新block id、parent_id和新文档标题造成的必然差异，核对卡片图标、颜色、网格列宽与空白块。卡片图标若与模板不一致，先处理复制异常，不能带着默认图标继续批量填充。
5. 回填只修改副本中既有文字子块、链接和图片；Callout容器及其样式保留。修改后回读，必要时页面目视验证。模板中的示例、旧主体事实与占位必须替换或移除；单人层级及十四平台固定正文仍按各自合同。
6. 复制结果不明时先查询实际新建结果，不能盲目重放POST；复制失败时核对权限、来源类型和目标目录，在既有故障止损范围内修复。未经验证，不降级为空文档重建再承诺版式一致。

历史方法保留：原生复制后按内容与结构对比，排除新旧文档 ID、标题，再验证图标和后续局部写入。旧验证文档与任务证据未收入复现包，不能把历史描述作为新机器验证结果。

官方接口：[复制文件](https://open.feishu.cn/document/server-docs/docs/drive-v1/file/copy)、[获取根目录](https://open.feishu.cn/document/server-docs/docs/drive-v1/folder/get-root-folder-meta)。

页面验证也已通过：顶部奖杯与两个图钉、基本信息五个图标及灰底双栏均实际显示正确，文字填充后仍保留。完整验证记录见原生模板复制验证（历史任务证据未随包分发）。

## 十四平台增量回填

每个平台完成后即可写入，不等待全部调查结束：

1. 列出目标区块，定位该平台的有序列表标题和下一平台标题；
2. 读取该区间的当前内容，确认是否已有用户修改或上轮内容；
3. 按 `platform-format.md` 生成该平台最终区块，只替换该区间；
4. 回读该区间，确认没有重复、错位或误删；
5. 如新增风险，再局部更新顶部风险摘要和对应 `举例N`，不重建整份文档。

十四个平台标题必须是同一组连续有序列表。平台内的编号使用全角 `（1）`、`（2）`……；`境内其他内容`和`境外其他网站`的子平台各自从 `（1）` 重新开始，并保留各自固定尾句。

创建、追加、上传或补丁返回不明确时，先回读实际状态，再决定是否重试，避免重复插入。不要因为接口超时直接重放写操作。

## 样式、链接与图片

- 替换有样式的文本前，读取原区块的 text elements，保留需要的粗体、颜色和链接。`背调结果：`与结果值使用分开的加粗 run；采用调查助手按三级标准给出的结果并套用模板既有颜色，不等待用户或上游分级。
- 主页和搜索模块显示完整 URL，并只让该完整 URL 可点击；显示文本与链接目标一致。
- 平台风险原帖 URL 放在截图后方，独立显示完整 URL。顶部举例不放外部 URL；只要存在举例，就必须把简短风险句链接到对应平台事实区块。
- 图片使用当前可用的飞书图片上传能力获得 `file_token`，创建或定位 `block_type: 27` 图片块后，以 `replace_image.token` 写入，再回读确认位置与归属。若调用本地上传器，其文件校验仅是上传实现细节，不作为业务输入、研究证据或交付门槛。
- 跨文档迁移图片时，旧文档的image token不能直接绑定新图片块：2026-09-12实测会返回`1770013 relation mismatch`。将已核验的原本地证据上传到新块，`parent_type=docx_image`、`parent_node=新图片块id`、`extra.drive_route_token=新文档token`，取得新token后替换。文字和内部链接按旧新block id映射迁移，图片只换绑定，不改变证据内容。原文档保留至新副本回读和图片目视验证通过。
- 上传前打开截图复查：只保留账号归属、帖子文字或图片主体，以及必要的转发／引用／点赞关系；不得出现标签栏、地址栏、书签栏、任务栏、通知、其他页签、聊天窗口或无关私人信息。第三方评论截图默认遮掉与事实无关的头像、昵称和用户编号。未裁切整屏图只能暂存在任务 `process` 目录，裁切成品确认可用后删除。

## 授权或接口故障

### Callout图标未按参数改变

2026-09-12补验：官方CLI公开源码中的`POST /open-apis/docs_ai/v1/documents/{id}/fetch`能返回带样式的XML；对应PUT `block_replace`接受`<callout emoji="❤️">`却实际创建`bulb`，即使返回success且warnings为空。已回滚原卡片正文、颜色、位置和gift图标，回读区块总数恢复。该路线目前也不能解决指定图标；不能再因官方XML列出emoji属性而重复试验。块替换会改变块ID，回滚和后续操作须重新读取。实测文件：`新任务过程目录/历史验证证据未保留`；[官方更新实现](https://github.com/larksuite/cli/blob/main/shortcuts/doc/docs_update_v2.go)、[同类问题843](https://github.com/larksuite/cli/issues/843)。仅服务端行为有明确更新时再复验。

2026-09-12合成主体021文档实测：创建时传入`emoji_id: trophy`，回读仍为`gift`；已撤回仅用于验证的新空块，原内容保留。随后只读复查原8个Callout仍为gift。当前MCP的单块patch schema和[官方Python SDK的UpdateBlockRequest](https://github.com/larksuite/oapi-sdk-python/blob/v2_main/lark_oapi/api/docx/v1/model/update_block_request.py)未列出`update_callout`，不能猜造此字段反复提交。SDK的Callout模型含emoji_id只说明数据模型有该属性，不证明服务端支持对应写入。

结论已于2026-09-12更新：上述失败仅证明当时“重建或替换卡片时指定图标”未生效，不能推出正确新建报告受阻。新报告改走已实测成功的原生模板复制，既有图标直接保留，不再循环试写emoji参数。已经填充的旧文档仍按当前授权保护内容和手工修改；修复或迁移前保留原文，验证事实、图片与内部链接，不能把测试副本冒充旧报告已修好。不得为解决图标转用界面编辑正文。

这是截至验证日期的能力记录；后续官方接口新增支持时，按一次小范围成功实测更新本条，不永久判定平台不支持。十四平台正文格式和模板要求不因此改变。

### 其他已验证办法

- 图标、颜色、列表编号等字段都按“请求结果＋独立回读＋必要时页面效果”验收。连续编号的现有处理办法以主Skill为准，不再积累一份重复版本。
- 飞书正文处于内部滚动容器；只读版式检查使用实际容器滚动，规则见调查Skill的通用排障方法。2026-09-12已验证正文滚动后画面改变，不用window.scrollY是否变化判断检查范围。

身份恢复只按[主 Skill 的统一预检与四种状态](../SKILL.md#飞书身份预检与恢复硬门槛)：普通到期先走静默续权，只有 `CODEX_OAUTH_REQUIRED` 才进入原账号既有权限的 OAuth。技术故障不转述成缺授权，浏览器审阅失败不使正常 API 失效；新增 scope 或实际用户专属验证才请求对应介入。一次有界恢复失败只挂起该操作，继续其余已授权工作，不回退到界面编辑正文。

## 最小回读

普通交付结束前通过 API 检查：

- 标题和目标 token 正确，模板没有被修改；
- `风险摘要`、`基本信息`、`背调详情`及其 H1/H3 层级正确；
- 奖杯与图钉 Callout 的颜色、图标和子块结构正确；API 可证明链接字段与目标区块存在；有风险内链时，交付调用方按[跳转记录示例](../../review-feishu-background-check/references/review-context-schema.md#风险内链实际跳转)把真实跳转与展开正文可见结果写入 `visual_check.jump_checks`，不能以 `clicked=true` 代替。无此类内链不加点击任务，已确认且绑定未变的记录直接沿用；
- 基本信息两个 50/50 网格、四个图标、代表作 Callout、必要空白块和十四个平台顺序正确；
- 本轮内容只出现一次，用户手工修改仍在；
- 风险事实、截图和原帖 URL 的顺序正确，图片可显示且没有无关隐私；
- 主页／搜索 URL 完整、可点击且落点一致；
- 平台内全角编号连续，两个“其他”章节的子平台编号和固定尾句正确。

发现具体问题后修正并回读受影响区块。普通交付复用已有调查记录，按[文案与来源引文检查](feishu-style-guide.md#文案与来源引文检查)完成扫描与全文语义审阅，保留有来源的引文，将助手附加说明改为具体事实。当前版本通过终审后发送成品链接，待核项记录其缺失材料并继续其他已授权工作。

## 显式审计模式

用户明确要求取证级、穷尽审计、研究包或机器校验时，按 `handoff-contract.md` 或 `handoff-targeted-contract.md` 读取 payload，并使用现有 validator 和上传安全检查。审计模式规则不得反向约束普通交付。
