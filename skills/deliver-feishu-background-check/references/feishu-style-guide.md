# 飞书背调版式与文风

## 格式来源

在线模板与用户已验收云文档共同决定普通交付格式：

- 使用本机配置中的正式 `template_document_token` 和 `style_reference_urls`，不要使用合成链接。

每次新建报告前用飞书 API 读取一次模板结构。用户当前指令优先；用户已手工修正并认可的目标文档优先于旧静态说明。模板和参考文档只读，不能复制其中的主体事实。

单人报告可配置用户验收过的两类只读参考：单风险顶部与基本信息、十四平台编号和空白间隔；各平台主管结论的位置与固定措辞只以 `platform-format.md` 的逐项标准为准。

## 单主体文档

页面标题使用 `M.D-对象名`，月日不补前导零。正文依次为：

1. H3 `风险摘要`；
2. 奖杯 Callout；
3. 有风险时，每个风险组依次使用 H4 `举例N【风险标题】`、图钉 Callout、简短事实段和截图；
4. 分割线；
5. H3 `基本信息`；
6. 两个双栏网格、代表作 Callout；
7. 分割线；
8. H3 `背调详情`；
9. 十四个平台组成的一组连续有序列表。

飞书 block 类型：

- H3：`block_type: 5`；
- H4：`block_type: 6`；
- Callout：`block_type: 19`；
- 分割线：`block_type: 22`；
- 网格／列：`block_type: 24 / 25`；
- 图片：`block_type: 27`；
- 平台有序列表标题：`block_type: 13`。

不要把通用模板中的 H1 主标题、H3 举例层级写回已验收的单人版式。用户指定其他样式时以用户指令为准。

## 风险摘要与举例

### 摘要、简单解释与正文的详略（2026-10-30 用户确认）

以下规则整理自 2026-10-30 用户确认的写法，复用信息分工，不沿用参考稿的对象、事件结论或局部版式差异。

| 位置 | 写什么 | 详略 |
| --- | --- | --- |
| 奖杯中的风险摘要 | 具体事件或风险名称，让读者一眼知道有哪些问题 | 每项一句凝练的短句，例如“游戏同人曲引发玩家圈层争议”；不堆日期、来源和经过 |
| 举例标题 | 沿用对应摘要的风险名称，放入“举例N【……】” | 不在标题中展开事件经过 |
| 举例下图钉中的简单解释 | 主体做了什么、争议点是什么；有必要时带关键时间、受众反应及会改变理解的回应，也可汇总在哪些平台有讨论 | 一句或一个短段落，比摘要名称具体；可以直接复用正文核心说明，不必刻意换词或再次压缩 |
| 对应平台正文 | 核心事件说明，以及该平台实际支持的事实、截图与完整来源链接 | 核心文案可以与图钉相同或基本相同；只有事实需要时才补更多经过，不规定正文必须比图钉长 |

一致关系：摘要的短风险名与举例标题对应，图钉解释与正文风险段的核心事件、主体、归因和结论对应。后两处允许直接复用同一段准确文案，不能为了制造层次强行换词、删细节或扩写正文。真正需要凝练的是奖杯中的风险名称；简单解释则应让人读懂事件。压缩时仍保留影响理解的关键事实，例如原言论与后来翻出的时间不同、网友解读与本人原话不同、当事人随后作出澄清。

不同之处主要在证据组织：顶部按事件汇总，可以在核心说明后补“微博和知乎均有相关讨论”等已经核实的跨平台信息，并通过图钉内链跳到正文；正文按平台落地，保留本平台截图、完整原帖 URL 和确有必要的补充事实。同一事件的其他平台若仅为转载或讨论，也可一句准确概括配证据，不要求处处重写长经过。复杂事件可在正文补时间线、回应及后续，但这不是每个风险项的固定要求。

例如，同一事件的图钉解释与平台正文可以使用相同的核心段落，顶部另补已核实的跨平台讨论；复杂事件则可在正文补充发布、回应、删除及后续说明。两种都合格，不能强制所有正文扩写。图钉已经承载的解释，不在图钉下额外加一段重复文字；这不禁止图钉与平台正文复用核心说明。

- 奖杯 Callout 固定使用 `background_color: 2`、`border_color: 2`、`emoji_id: trophy`。第一个子块固定写 `风险摘要`。
- 无风险时，在 `风险摘要` 子块后单独写一个 `无` 子块，不创建举例。
- 有风险时，在 `风险摘要` 子块后按 `1：……`、`2：……` 各写一个独立文本子块，不放外部链接。
- 同一具体风险主题合并为一个举例；仅仅同属“政治”“低俗”等大类不能强行合并。
- 一个举例对应一个主题。H4 `举例N【风险标题】` 保持普通标题，不设置链接。图钉 Callout 固定使用 `background_color: 2`、`border_color: 2`、`emoji_id: round_pushpin`；其简短风险句只设一处文内链接，指向该主题在正文中第一次出现的平台风险事实。
- 举例区须覆盖该主题已选入正文的事实要点并保留对应截图，可在一段简单解释中合并同一事件，不逐条镜像正文长句；每条入选事实仍须能对应到顶部解释，同一主题跨平台的证据按正文顺序排列。此处的完整覆盖不增加调查阶段取样额度。顶部不放原帖外部 URL；各平台主管仍保留事实、截图和完整原帖 URL。
- 同一主题跨平台出现时，顶部可合并；各平台章节仍分别写本平台的事实和证据。

顶部事实可以是正文事实的简明表述，不要求逐字复制长段落。每条顶部表述须与正文中的对应事实逐一绑定，保留行为、归属及影响判断的关键限定；可以省去在该上下文已清楚的日期、主体名和重复风险标签，不得改变事实或省略入选证据。审核按已审定的顶部文案及事实映射检查，不为满足逐字镜像把用户删掉的长句恢复。

用户完成手工审定后，以最新稳定版本为本次交付依据。删除或合并风险须联动核对奖杯摘要、举例、平台正文、图片、内链及连续编号，清除旧摘要残留；不因风险数量减少自动降低结果等级。只修复必要的机械遗漏，保留人工压缩的措辞，不将旧稿或旧校验预期重新写回。将用户实际删改与助手对其原因的推断分别记录，本次取舍不自动成为全局业务豁免。

## 基本信息

保持在线模板的两个 50/50 双栏网格，按固定位置依次放置：

- `背调对象：……`；
- `类别：……`；
- `背调结果：……`；
- `简介：……`。

四个字段的 Callout 图标默认依次为 `bust_in_silhouette`、`books`、`heart`、`ledger`。四张卡必须有可见的中灰背景；从模板原生复制保留实际颜色与图标，API省略颜色字段不等于页面缺少背景，不为补写字段重建卡片。单份文档中用户已明确认可的图标改动只对该文档有效，不变成通用模板。首次终审或布局指纹变化时通过一次页面实显核对；不强制保存截图，纯文字修订且布局指纹不变时复用视觉 PASS。`背调对象`、`类别`、`简介`整行加粗；`背调结果：`和结果值分别作为加粗文本 run。两个网格的四列各只放一张 Callout，不加列级空白子块；每张 Callout 内也只保留字段正文，不得添加尾随空白子块。

背调结果由调查助手按[三级分级标准](../../background-check-research/references/methods.md#背调结果分级)根据已核实事实判断，不要求用户或上游先提供；交付步骤采用该判断，最终交付前复核，不按风险数累积分级。保留模板既有颜色：`建议谨慎评估`为 `text_color: 1`，`建议评估`为 `text_color: 2`，`低合作风险`使用默认颜色。

从 2026-10-30 起，简介在已确认的身份和工作内容之外，还要自然介绍对象的社媒内容方向、是否有过重大争议，以及公开表达风格。结合实际阅读写一小段，不套“身份—内容—争议—风格”的固定句式，不再按旧有约30字的目标硬压篇幅，也不堆职业履历。人物可写作品宣传、生活分享、行业评论、直播互动等实际方向；品牌则介绍官方账号的产品、活动、联动和互动方式。风格用可观察的表现说明，如偏正式公告、口语化闲聊、经常直接回应网友，不能从国籍、职业或个别帖子推断性格。

有重大争议时简要点明已核实事件，详细经过放风险区和正文；零星差评或业务表要求记录的合作关联不自动改称“重大争议”。没有发现重大争议的表述须有实际核查支撑，未完成时不能预填“无重大争议”，可直接说明争议核查尚未完成。简介的判断须与全文一致，不复制整份风险清单，不机械给每个对象加“风格温和、无争议”等结论。出身地、机构等只用可靠来源确认的信息，未知时不臆造。

`代表作`优先选本人参与且有可靠资料可核实、在国内或国外较为知名的二次元游戏或二次元相关作品；国内外不分先后。没有合适的此类作品时，才选其他已核实作品。作品已有通行中文名时用中文，英文副标题可保留；角色名有可核实的中文译名则一并使用，拿不准时保留原文，不自行音译。不得因作品知名而推定同名者就是背调对象，或将未经核实的参与经历写成代表作。`代表作`保持中灰背景 Callout，使用 `emoji_id: white_check_mark`，每部作品一个普通文本块，不挂外部链接。

新建文档必须使用[原生复制模板](feishu-operations.md#原生复制模板)，保留模板既有卡片、网格、图标、颜色与空白块，再局部回填并核对单人版式。“复制区块树”不能解释为新建空白文档后逐块重建；字段参数相同不保证服务端创建效果相同。

## 十四个平台

顺序和写法固定：

`微博 → B站 → 抖音 → 小红书 → 知乎 → 网易云音乐 → 贴吧 → 豆瓣 → 境内其他内容 → X → Facebook → INS → 油管 → 境外其他网站`

每个平台标题出现一次，并在页面上连续显示 `1. 微博` 至 `14. 境外其他网站`。优先使用原生有序列表：首项 `sequence=1`，其余 `sequence=auto`，以页面实显确认连续编号。若 OpenAPI 回读丢失 `sequence` 且页面重复显示 `1.`，使用普通文本区块显式写入 `N. 平台名`。平台主管内部正文编号继续使用全角 `（1）`、`（2）`。具体模块、可删除项和固定结论见 [十四平台成品格式](platform-format.md)。

“境内其他内容”和“境外其他网站”中的具名平台各自从 `（1）` 开始。最后分别添加一个不编号尾句：

- `其他境内平台暂未发现相关账号或相关内容的负面及敏感信息。`
- `其他境外平台暂未发现相关账号或相关内容的负面及敏感信息。`

## 账号和平台归属

- 个人确认账号写“个人主页”；组织、公司或品牌写“官方主页”；项目写“项目主页”。
- 未确认账号写“疑似主页”“疑似官方主页”或“疑似项目主页”。
- 内容很少的疑似主页可按调查结论写完整 URL 和“无问题”。
- 内容较多但领域不符的疑似主页，写一句“发布内容主要为……，与背调对象领域不一致”，不把其内容归给主体。
- 疑似主页中的风险事实以“该疑似主页账号……”起句，顶部摘要和举例保持同样的不确定归因。
- Threads、TikTok、Pixiv、Bluesky、Spotify、Bandcamp、Patreon 等放在“境外其他网站”；额外境内平台放在“境内其他内容”。
- Instagram 简介或链接聚合页直接给出的 Threads、YouTube 等叶子链接属于强身份锚点；同头像、同旧 handle、姓名或艺名、职业和作品相互对应时，可以确认归属。不能机械要求目标平台再反向链接，也不能因为搜索结果来自第一位就自动排除；第一位结果仍需与上述身份特征一起核对。

## 风险证据和链接

平台风险项固定顺序：

`一句客观事实 → 截图 → 独立完整原帖 URL`

- 事实只写公开可见现象，不给主体作道德评价，不替上游作合作决定。
- “不给主体作道德评价”只约束成品措辞，不得被解释为排除业务风险。已核实的公开事实命中当前业务风险表或公司必记口径时，必须写入风险摘要、对应平台主管和结果等级；业务风险表在业务判定上高于助手内部规则、道德判断、价值判断及旧结论。可限制对私人属性的外推，但不能删除或降级已经成立的作品参与、制作、传播或公开表达事实。
- 主体原创、转发附言、本人回复、点赞、第三方讨论和媒体报道分别归因。
- 主页和搜索 URL 必须完整显示，并仅让完整 URL 文本可点击。
- 风险原帖 URL 位于截图之后，完整显示；不得隐藏在“原帖”“相关页面”、日期或作品名后。
- 受影响的平台必须各自保留事实、截图和 URL，不能只写“同上”。

## 截图版式与隐私

- 截图只显示账号名或必要头像、帖子文字或图片主体，以及证明转发／引用／点赞所需的关系标记。
- 裁掉浏览器标签栏、地址栏、书签栏、扩展图标、系统任务栏、通知、聊天浮层、其他页签和无关推荐。
- 必须遮挡无关私人信息时，只遮无关部分，不能遮风险事实、账号归属、时间或互动关系。
- 上传前逐张打开检查内容、归属和隐私。整屏截图或能看到其他标签名的截图不得进入飞书。
- 第三方评论截图默认遮掉与事实无关的头像、昵称和用户编号，只保留理解来源与讨论所必需的信息。未裁切整屏图只能暂存在任务 `process` 目录，裁切成品确认可用后删除。
- 截图数量少时使用单图或双栏；文字较小、竖屏或内容较密时减少列数。不同平台的截图不要混在没有标签的同一组中。
- 删除空图片区块。截图在顶部举例和对应平台章各出现一次是允许的，但不能拿同一截图代表不同事实。

## 文风

使用简短、自然、事实性的中文。成品只出现：

- 模板要求的标题和固定模块；
- 已确认的基本信息；
- 平台链接与极简结论；
- 风险事实、截图和原帖 URL。

不要写调查过程、覆盖数量、翻页轮次、登录状态、工具、API、模型、脚本、schema、哈希、置信度、候选排序、校验信息，或向读者解释“本批只核查了多久”等内部范围话术；平台合同本身要求的时间字段照写。不要写夸张形容词、道德评价、分析套语和无法由原内容支持的法律结论。

### 全篇免责文本禁令（硬门槛）

交付核查发现任何形式的免责说明、证据边界套话或其变体，一律打回为 `FAIL`，禁止 `PASS`。范围覆盖全篇：标题、正文、风险摘要、基本信息、表格、卡片、脚注、图注、引用、图片内文字、来源说明、人工审核途径及附录等；版权、法律、第三方来源和直接引用均无例外。

例如“仅供参考”“不构成法律意见”“不保证完整准确”，以及通过“不能据此证明”“不代表”“不足以认定”等句式泛化解释证据效力、限制报告责任的套话，都须按完整语境审阅，不能因未出现“免责”字样而放行。用户指定的打回例为：**公众号“原创”标记也不证明发布者是家属、继承人或作品版权方。** 将这句话放到版权小节、图注、引用或人工审核途径，或换成同义措辞，仍为 `FAIL`。

必须做全篇语义审阅。关键词、正则或示例清单只辅助定位，不能覆盖所有形式，也不能以零命中证明合格；判定不能只依赖是否命中上述示例。不得通过挪动章节、改标题、改称谓或改措辞保留原免责语义。返修应删除免责成分，直接陈述调查结论与必要来源归属。

直接调查结论如“未找到版权联系人”“版权方尚未确认”，以及“该资料由卖家发布”“该说法来自某篇文章”等必要来源归属应保留。真实未完成状态和待确认事实仍须准确写出，不得为了删除免责文本而将未核实内容写为“无问题”、无相关结果或已经确权。

## 合并多主体

默认一人一份文档。用户明确要求多人同文档或指定共同交付文档时，先在个人云空间独立稿完成正文并审阅，再定点写回共享文档，保护其他成员区块。合并版式为：

- 文首集中一个 H1 `风险摘要`；只为有风险主体建立 H2 `对象名风险摘要` 小节，按**全组派单顺序**放置。若所有主体均无风险，不放空的总风险摘要。
- 每个有风险主体的奖杯摘要和各 `举例N` 均在文首该主体小节内；举例列齐本主题正文全部入选事实与截图。H4 标题不加链接，橙色图钉 Callout 的简短句设唯一文内链接，跳到本主题正文首次出现的平台事实。顶部不放外部原帖 URL；各平台原址仍完整保留。
