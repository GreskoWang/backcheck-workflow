## 配置与模板

先在工作区执行 `Setup-Backcheck.ps1`，再加载 `recovery-session-env.ps1`。本机路径与账号配置分别位于 `config/runtime-paths.json` 和 `config/backcheck-local.json`，不得复制另一台机器的凭证或运行状态。跨机器安装步骤见工作区 `docs/INSTALL.md`。

业务与写作方法保留在本 Skill 的 references 中。正式云模板由当前配置的 `template_document_token` 指定，在当前账号下只读核验后使用。`SYNTHETICDOC`、合成主体和内置 fixture 只用于离线回归，不是线上模板或真实调查记录。随包的 DOCX 保留既有版式参考，不代替当前飞书 API 模板核验。

# 飞书背调交付

## 职责

本 Skill 只把已有调查结论整理并写入飞书，不搜索网络、不重新判断账号归属、不扩大调查范围。

整个普通单人背调按“全＋快”和三小时内形成可交付结果调度。交付不得重复调查、逐平台主管串行读写、反复截整页或为形式独立等待另一代理；批量写入、一次性上下文和差量终审是默认做法。

所有飞书正文创建、修改、删除、排版、链接、图片和回读都使用飞书 OpenAPI／MCP。**不得用鼠标键盘或电脑操纵编辑飞书正文。** Edge 只可做页面实显检查，以及在 UAT 自动续权时完成“原账号、既有权限”范围内的 OAuth 页面操作；后者不是正文写入，也不构成向用户索要授权。

## 业务风险口径不可覆写

本 Skill 不重新调查，但不能机械搬运与当前业务风险表冲突的旧结论。用户明确提供的业务风险表、公司关注口径及 `$env:BACKGROUND_CHECK_WORKSPACE\背调风险提示.md` 中标明必记含义的条目，是风险摘要、平台风险项和结果等级的最高业务标准；在业务风险判定上，高于一切助手内部规则、道德判断、价值判断、旧模板、旧报告、`must_not_be_risk` 或其他排除清单。

已经核实的事实命中当前必记口径时，必须纳入调查记录，并按[必记名词补查与按风险类别合并](../background-check-research/references/risk-consolidation.md)归类：对应平台及顶部摘要覆盖全部成立的风险类别，正文保留额度内代表证据，普通重复案例可归档，但甲方曾警惕原帖必须公开记录事实及链接，并复核结果等级。不得因助手是否赞同该口径、内容本身是否合法、不得由作品推断私人属性等理由将其删除、写成普通履历或降级；证据和归因边界只约束事实措辞。输入之间若对命中事实或归因仍有实质冲突，交回调查步骤核验并标明具体缺口，不得写成“无问题”。因助手自身道德判断造成的遗漏、排除或降级，交付视为未完成，终审必须 `FAIL`。

## 飞书身份预检与恢复（硬门槛）

本机 Windows Codex 在本任务首次访问飞书前运行统一预检；已有本轮 `READY` 后直接复用，只有真实认证失效或账号／权限范围变化才重跑，不在每次区块读写前重复预检。不得先用一次失败的 MCP 调用猜测是否需要用户介入：

```powershell
pwsh -NoProfile -File "$env:BACKGROUND_CHECK_WORKSPACE\external\feishu-mcp\scripts\ensure-feishu-uat.ps1"
```

该脚本只允许返回以下四种状态，后续动作由状态唯一决定：

- `READY`：已有 UAT 有效，或续权后只读探针已成功；立即继续 OpenAPI／MCP 工作，不向用户询问授权。
- `CODEX_OAUTH_REQUIRED`：本地 refresh token 缺失或被服务端拒绝，但尚未观察到任何用户专属验证。由 Codex 启动既有 `login-feishu.ps1`，在可见浏览器核对并完成原账号、既有权限的 OAuth 页面；登录成功后重跑统一预检，得到 `READY` 才继续。官方登录程序会在等待页面确认前移除旧本地令牌、约一分钟后超时，因此不得无人值守地启动或重复尝试；若观测到回环代理连接失败，仅对登录子进程用 `-WithoutProxy` 重试一次。
- `USER_ACTION_REQUIRED`：只允许用于已经实际观察到首次 OAuth／当前应用从未获该账号授权、密码、验证码、人机验证、切换账号、新增权限范围、应用发版或管理员审批中的一项。必须报告具体命中项；仅有“浏览器没有自动完成”“登录失败”“令牌失效”或超时，不满足该状态。
- `TECHNICAL_FAILURE`：网络、代理、脚本、回调或接口发生技术故障；继续做一次有界诊断或恢复，不得把它表述成用户未授权。

`user_access_token invalid or expired` 只触发统一预检的直连探针、既有 refresh token 静默续权及续权后探针，不构成 `USER_ACTION_REQUIRED`；只有返回 `CODEX_OAUTH_REQUIRED` 才进入既有 `$env:BACKGROUND_CHECK_WORKSPACE\external\feishu-mcp\scripts\login-feishu.ps1`。原账号、既有权限的续权已有持续授权，可由 Codex 完成的同意页不转交用户。失效回环代理仅按脚本隔离相应子进程并有界重试，不改系统代理。每次续权后必须重新执行只读 UAT 探针；没有得到 `READY` 不得进入正文写入。

浏览器握手、截图、渲染或图钉跳转失败，与飞书 API 身份分开诊断；API 正常时不重新拉起 OAuth。图标或实际跳转未验证只挂起相应终审项目，不妨碍其他已授权内容写入、回读和本地整理；不能据此宣称成品 PASS。

禁止临时重写登录流程、把 App Secret 放入命令行或自行拼装新的 OAuth 权限。真正的云端／远程环境若缺少本机 DPAPI 凭据、已安装的本机授权脚本、`localhost:3000` 回调或原账号浏览器登录态，应报告本机授权设施不可用，不能假称已自动续权。Codex 的工具审批提示与飞书 OAuth 是两类状态；`default_tools_approval_mode = "prompt"` 不能作为要求用户重新登录飞书的理由。任何“需要你授权”的答复必须同时给出：已运行的预检命令、返回状态、实际观察到的用户专属阻碍；缺一项即禁止作此结论。

本节或 UAT 恢复脚本发生修改后，必须运行 `scripts/validate-identity-contract.ps1`。该校验未通过时不得把新的身份规则投入交付流程。

## 普通模式的结论来源

按以下顺序读取：

1. 用户在当前任务中明确给出的人工核查结果；
2. `$background-check-research` 在当前任务中已完成的逐平台结论；
3. `$env:BACKGROUND_CHECK_WORKSPACE\YYYY-MM-DD\<对象>\调查结论.md`；
4. 续写或修正时，目标飞书文档的当前 API 回读内容。

普通模式不寻找 `research_payload.json`，复用已有正文、媒体、逐条阅读及名词来源记录，不新建研究包、全量查询回执、质询逐轮哈希或重复台账。用户已有结论按明确范围同步。

普通交付消费当前逐平台结论、风险证据、名词提取及甲方真实态度记录，不重造材料。正文、媒体或实际搜索未完成仍保留具体缺口；词义未知交给轻量质询，不视为未完成全平台调查。

复用 `discovery_review` 的实际阅读、完整名词和来源映射，由共享发现检查核对。不得伪造阅读或切换人工模式；不再要求调查查询子代理和逐词查询回执。

使用新的批量缓存路线时，交付只消费调查者实际完成阅读／媒体核验后的四态结论；`job`结束、下载／拼图完成、JSON格式有效和批次导出均不是“无问题”。复用结构化结论以批量生成和更新当前合同区块，原生模板、业务风险表、十四平台措辞与飞书终审保持。不得导入外部render脚本把缺失平台默认写“无个人主页；无问题”的行为，也不把Markdown复制版替代指定飞书成品。缓存／覆盖辅助工具不反向成为普通既有报告的取证门槛。

每个平台的最小输入为：

- 主页状态和 URL：确认主页、疑似主页或无主页；领域不一致时带一句内容概括；
- 按平台主管合同要求提供实际平台内名称或账号名搜索 URL；网易云音乐与INS不写搜索结果链接，贴吧不写个人主页模块；
- 无风险状态 `无问题`，或风险项的一句客观事实、归因、隐私裁切截图和原帖完整 URL。

输入中的 `无问题` 表示已核查且未发现需记录问题，或已按访问结项规则确认客观不可访问并结项，不表示没有相关结果。写入前先核对实际结果和完成范围，再选择 `platform-format.md` 对应模块的句子；不得把存在转载、署名或讨论的搜索写成无相关内容，也不得给仍可执行却未执行的核查填干净结论。

若输入只有“无问题”而没有说明搜索是否出现相关内容，不得推导出“无相关内容”。复用当前任务的实际搜索记录；记录仍不足时在该模块写明“尚未完成”及缺少的检索依据，交回调查步骤继续处理，不改写成确定结论。用户截图、原页或回读发现反例后，先纠正对应结论，再核对其余平台是否用了同一错误套句；旧文档和模板不能充当事实证据。

每条“无相关内容／无涉及内容／无个人主页”都要能在当前调查记录中找到对应的有效检索依据；找不到就改为准确的未完成状态，并把缺口交回调查步骤继续处理。外部 `site:` 查询零结果仅说明相应搜索引擎当前索引未检出，不得写成平台没有内容。回读时逐条核对这些否定句，不以链接可点击、区块写入成功或模板格式正确代替事实核对。

输入缺少某个风险项的截图或原帖 URL 时，只暂停该风险项；仍可写入其他已完成平台和无风险结论。

## 强制成品审阅门槛

每份新建或修改后的背调文档，在把飞书 URL 表述为“成品”“完成”或“已交付”之前，必须调用 `$review-feishu-background-check` 对最新稳定 revision 做只读终审。

- 当前任务事实、用户指令和 `platform-format.md` 可一次性编译成审阅上下文；事实不变时跨 revision 复用，不重复调查或手工重建十四平台预期；
- 全篇执行[文风中的免责文本禁令](references/feishu-style-guide.md#文风)：任何形式的免责说明、证据边界套话及其变体均为 `FAIL`。首次实际通读全篇，后续按审阅 Skill 的全文指纹与语义差量规则保持全篇覆盖；版权、法律、引用来源及任何章节均无例外，关键词零命中不能代替语义审阅；
- 读取当前任务适用的业务风险表与公司关注口径，把全部已核实命中项同风险摘要、平台章节和结果等级反向比对；因助手自身道德或价值判断造成的遗漏、排除或降级一律 `FAIL`，不得被格式、链接、视觉或免责检查通过所覆盖；
- 业务风险复核须绑定实际读取的当前风险表路径和 SHA-256；每条入选终稿的业务风险代表事实分别记录，并绑定当前摘要、平台主管事实和结果区块的精确 `{block_id,text}`；普通同类重复事实可留原档案；甲方曾警惕原帖必须有公开事实和来源绑定。主交付校验器必须调用共享业务门禁；缺失／过期记录不得产生 `delivery_validation_passed=true`，伪造来源、虚构区块或显式业务冲突必须 `FAIL`；
- 不为了形式上的“独立终审”专门创建代理；仅甲方质询需要一个实际新建的无缓存角色代理，调查阶段不再创建名词查询代理；
- 审阅先批量获取完整块树并全量逐字、逐链接、逐结构检查。确定性 `FAIL` 立即返修，不做截图；
- 新建或布局变化才做一次最小页面检查；仅文字/链接修正且 `layout_fingerprint` 未变时复用视觉 PASS；
- `FAIL` 时只做定点修正，再对新 revision 重跑全量确定性检查；只有布局指纹变化才重做视觉；
- `BLOCKED` 时处理实际缺口，不能交付，也不能无上限轮询；
- 只有服务端最新 revision 的 `business_risk_review`、全篇免责语义和完整终审均为 `PASS`，且回执 token/revision 一致，实际背调还通过独立的 `$client-challenge-background-check`，才能发出成品链接。后续写入使文字 PASS 失效，但不会在布局指纹不变时强制重截整页。

实际背调先按[甲方质询技能](../client-challenge-background-check/SKILL.md)进行首轮全表与必要增量复评，再成稿终审。任一轮曾警惕永久入稿，最终疑问列待确认；同类合并不能删掉必记原帖。不得把说服甲方放松作为目标，不要求前置成品终审。

同一任务保存 `review_context.client_challenge_review` v3，字段见[轻量契约](../client-challenge-background-check/references/review-contract.md)。成稿后取得最新终审，最终 release 调用同一 v3 提交检查；`--audit-only` 可用于终审过程，不代表最终提交。

此门槛审阅业务风险表与已核实事实的一致性、成品格式及全篇免责语义，不要求 research payload、逐帖或证据哈希、逐帖台账或取证级证据包；规则表与成品自动指纹仍用于防止过期审阅，也不改变调查事实的完成标准。不得通过挪章节、换称谓或改措辞保留免责语义；直接调查结论和必要来源归属仍须保留，未核实内容不得改写为“无问题”。

## 格式依据

用户当前明确指令最高。其余格式按职责分开：

- 在线模板的 API block tree 决定标题层级、父子顺序、Callout、网格、列宽、图标、颜色、间距和空白块；
- `platform-format.md` 决定十四个平台名称、顺序、模块、固定句、编号、链接位置和截图位置；模板占位文案不得覆盖这份正文合同；
- 用户最近明确认可的目标文档手工修改受到保护；
- `feishu-style-guide.md` 和 `feishu-operations.md` 补充前述两类规则没有规定的部分。

在线模板：

- URL：`https://my.feishu.cn/docx/SYNTHETICDOC0000000000000001`
- token：`SYNTHETICDOC0000000000000001`

模板永远只读。新报告通过原生复制取得模板的完整格式，随后清除或替换其中的示例事实、风险数量、链接和占位文案；这些示例不能作为目标主体的调查结论交付。

单人报告若已有用户验收过的同类云文档，先读取并按其真实 block tree 对齐；本 Skill 当前固定参考为：

- 单人单风险顶部与基本信息：`合成只读参考022`（token：`SYNTHETICDOC0000000000000003`）；
- 十四平台编号、结论和间隔：`合成只读参考023`（token：`SYNTHETICDOC0000000000000004`）。

两份参考均只读。单人报告采用 H3 `风险摘要／基本信息／背调详情`、H4 `举例N`。十四平台标题必须使用飞书原生有序列表，首项 `sequence=1`、其余 `sequence=auto`，在页面实显中确认自动连续显示 `1. 微博` 至 `14. 境外其他网站`。此要求适用于单人报告、团队合并及原样回填，不得用手写编号的普通文本替代。回读字段缺失或页面重复显示 `1.` 时，继续核对并修复原生列表结构，再确认实显；接口成功或手写编号看似连续均不能代替验收。

## 团队合并文档

仅在用户要求多人同文档、或已明确指定共同交付文档时使用[合并多主体版式](references/feishu-style-guide.md#合并多主体)。先在个人云空间的独立文档完成本机对象的正文和审阅，再按派单映射及共享文档当前区块树，把已审阅内容定点写回同一共享文档；共享文档不承担调查过程稿和未审阶段稿。写回前后均核对 revision、对象边界、风险摘要在全组中的顺序及非本机区块，保护其他成员和用户手工改动；不明的槽位或并发改动先重新读取，不按旧 block id 覆盖。共享文档最新 revision 仍须单独通过终审，独立稿 PASS 不能代替。除需求方明确指定的交付正文外，不写调查方法、覆盖数量、登录／工具情况、内部时间窗说明等过程话语。

## 普通交付流程

1. 用飞书 API 读取在线模板的标题层级、Callout、网格、平台列表和样式。一次任务只需读取一次；续写同一文档时直接读取目标文档。
2. 单人交付如当前任务或 `调查结论.md` 已记录目标飞书 URL，回读并续写该文档；否则使用飞书原生复制文件接口取得独立文档，再用新文档返回的真实 block id 替换内容。团队合并交付先读取指定共享文档定位槽位，但增量写入先进入个人云空间独立稿，审阅后才定点回填共享稿。不得把“复制模板”实现为新建空文档后逐块重建卡片；先回读确认图标、颜色、网格、列宽和父子顺序，再按适用版式与十四平台合同局部填充。操作及失败处理见[原生复制模板](references/feishu-operations.md#原生复制模板)。
3. 指定一个交付写者。研究可以并行，但同一目标文档的 API 写入按修订顺序串行。
4. 一个平台结论到达后，先核对事实分支、固定模块和文风，再在对应工作文档增量更新；用户指定“定稿后才写”的文档只接收已经审定的交付段落，缺口保留在本地或独立工作稿。团队共享稿只接收已审阅的成品。先读当前区块，再定点替换，不重建整份文档。
5. 无风险严格按`platform-format.md`的新话术总表写模块和二选一结论。网易云音乐与INS只写主页模块，贴吧只写主题贴吧与关键词搜索；其余平台写合同规定的主页／话题／搜索模块。风险项按“一句事实 → 截图 → 原帖完整 URL”写入对应平台。
6. 新风险出现时同步更新顶部“风险摘要”和对应“举例N”，按[风险说明与证据的分工](references/feishu-style-guide.md#风险摘要与举例)写作：奖杯摘要使用凝练风险名，举例标题沿用该名称；图钉和平台风险说明均用少于30字的短句，不带时间或对象姓名，不复述帖子，只提炼核心行为或争议，保留疑似账号、转发和第三方等必要归属。原文与经过由截图和来源承载，不另加重复解释；用户明确要求详细经过时再按其要求展开。每个平台每个风险表类别通常选最多4个例子详细展开及截图，必记原帖的简洁事实和来源仍完整保留，通常推荐3—4个，少量足以说明也可收口；原调查与名词质询补查不另开额度。先按类别合并相同事件，补充事实更新原段落，不重复追加；不同类别各建索引，不为凑数补例，也不为顶部另扩采样。顶部解释覆盖全部入选事实要点并保留相应证据，各平台各自保留事实、截图和原帖 URL；已选为终稿代表证据但未放顶部的平台主管事实保留；普通重复事实可留原档案；甲方曾警惕的原帖即使不选为详细举例也须公开简述事实和链接。本人发布、转发和第三方内容分别归因。H4 举例标题不加链接，橙色图钉 Callout 中只设一处文内链接；普通风险指向该主题首个入选平台主管事实，用户明确要求联动风险不在平台主管重复时指向联动表格对应行。
7. 基本信息只用已确认的名称、类别、简介和代表作。自2026-10-30起，[简介](references/feishu-style-guide.md#基本信息)还须自然简述实际社媒内容方向、重大争议情况和表达风格，不套固定模板、不把未完成写成无争议。`背调结果`由调查助手按调查Skill的[三级分级标准](../background-check-research/references/methods.md#背调结果分级)判断，交付步骤采用该判断并设置对应颜色，不要求用户或上游提供结论。已有证据尚未分级时先由调查步骤补作判断，再填写；阶段判断不代表未完成调查已结束，交付前须按最终证据复核。
8. 每次写入后立即回读受影响区块。用户正在手工编辑或页面显示“保存中”时，不把中间块树当成最终修改；等待 revision 稳定后，一次批量回读标题、完整块树和 raw content。API 已能证明的文字、链接和结构不再用截图复核。
9. 成稿前完成 `$client-challenge-background-check` 的真实表态及事实复评；完成写入后调用 `$review-feishu-background-check` 审阅完整最新文档。确定性错误修正后重审，布局未变可复用视觉基线；最新终审及 v3 提交检查通过才交付。

独立工作稿可保留真实未执行项的“尚未完成”，不能留模板占位或预填干净结论；它不等于指定成品。已确认删除、封禁、关闭、隐私页面、限制查看或其他客观原因不可访问的项目，按[访问结项规则](../background-check-research/references/access-policy.md#客观不可访问项按无问题结项)记“无问题”并结束该项；不得写成待办或据此阻止成品交付、终审和 Goal 完成。实际访问原因保留在既有任务状态，正文不增加待恢复清单，也不虚构已读不可见内容。其他真实未完成模块继续处理。阶段回填、同步已有结论和格式 PASS 均不自行结束原研究范围；交付前分别核对当前用户范围、研究剩余项与最新文档终审。进度用 commentary，随后继续可做工作。用户接管、暂停或缩范围按原话记账，不能称技术已修复。

## API 写入规则

- 使用 `useUAT: true` 的飞书工具读取模板和目标文档；创建、区块写入、图片替换和回读方法见 `feishu-operations.md`。
- 身份状态只按本 Skill 的“飞书身份预检与恢复（硬门槛）”处理；未运行统一预检、未取得 `READY`，或只依据一次接口报错时，禁止开始写入或向用户宣称必须重新授权。
- 每次修改前确认目标 token 不是模板 token。原生复制请求允许将模板token作为只读来源file_token，返回的新token才是后续修改目标；不能把这一来源参数误判为修改模板。复制后重新列出区块，只使用新文档返回的真实block id。
- 创建、追加或上传结果不明时，先回读目标状态再决定是否重试，避免重复内容。
- 用户已经手工修改目标文档时，先回读并保护这些修改，只补当前明确授权的范围。
- 普通接口故障只做一次刷新或重连；不得改用界面编辑。认证恢复的重试次数、代理隔离和用户介入条件不得另行扩写或放宽。

## 截图与链接

- 风险截图只保留账号归属、帖子文字或图片主体、必要的转发／引用／点赞关系。
- 截图不得出现浏览器标签栏、地址栏、书签栏、系统任务栏、通知、其他页签、聊天窗口或无关页面内容。上传前必须打开复查；发现无关私人信息就重新裁切或局部遮挡。
- 主页和搜索 URL 显示完整 URL，并让该完整 URL 可点击。
- 平台风险原帖 URL 放在截图之后，单独显示完整 URL。
- 顶部举例不放外部 URL；H4 标题保持普通文字，只在橙色图钉 Callout 的简短风险句设置文内链接。普通风险指向首个入选平台主管事实；用户明确要求联动风险不在平台主管重复时指向联动表格对应行。

## 最小回读

普通模式只检查：

- 标题与目标文档 token 正确，模板未被修改；
- 单人文档三个主区为 H3、举例为 H4；合并文档使用文首总风险区、主体纯姓名 H2，个人正文仅 H3 `基本信息／背调详情`，无风险者没有空风险摘要模块；各主体基本信息卡和十四个平台顺序符合适用版式；
- 基本信息四个字段位于两个 50/50 网格中的中灰色 Callout 卡片内；四列各只有一张 Callout，不带列级空白子块，Callout 内也不加尾随空白子块。四张卡及代表作卡的默认图标分别为 `bust_in_silhouette`、`books`、`heart`、`ledger`、`white_check_mark`；仅保留当前文档用户明确认可的图标例外，不把该例外扩展成通用默认；代表作每部作品独占一个文本块；
- 合并文档文首只列有风险对象，按全组派单顺序排；每个风险举例覆盖该主题全部入选事实和截图，未入选平台主管事实仍保留；H4 无链接，唯一内链在橙色图钉句，普通风险指向首个入选平台主管事实，用户明确要求联动风险不在平台主管重复时指向联动表格对应行；其他成员区块保持不变；
- 十四平台主管文字、模块和链接由完整块树确定性全量检查；仅当有序列表 `sequence=auto` 或布局指纹变化时，才用一次页面检查确认连续显示 `1` 至 `14`。每个平台的无风险结论必须按 `platform-format.md` 的逐项固定措辞直接追加在指定主页或搜索链接后，不得抽成独立结论块或统一写成“无问题”；平台末尾保留一个空白间隔；
- 本轮平台内容已写入且没有重复；
- 无风险措辞、疑似主页标签、风险事实、截图和 URL 位于正确章节；每条结论须与调查事实相符，分别核对“无相关结果”“有相关结果但核查未见问题”“尚未完成”。格式措辞与证据冲突时按事实和用户最新要求处理，不能机械套句；
- 图片能显示，且裁切后没有无关隐私；
- 合同要求出现的主页、话题和搜索链接均可点击且显示完整 URL，风险 URL 完整；网易云音乐与INS不得多出搜索链接，贴吧不得多出个人主页模块；
- 用户手工修改仍在。

修正本 Skill 自查发现的真实问题后，必须再通过 `$review-feishu-background-check` 的格式终审；普通模式不运行研究包或取证 validator，但实际背调仍须运行独立甲方质询门禁。交付背调全稿前，逐项对照原始要求、研究未完成项和目标文档：还有未查看内容、未查平台、缺少证据、未核对写入项、格式终审未 PASS 或甲方质询未完成时继续处理，不能把“阶段稿已写入”当作完整任务完成。仅在研究与交付条件均达成、最新文档格式 PASS 且 `$client-challenge-background-check` 放行后，才完成对应调查 Goal；此 Skill 的一次增量回填不得结束研究 Goal。

## 取证级或机器校验交付

只有用户明确要求“取证级”“穷尽审计”“研究包交付”或“机器校验”时，才切换证据审计模式；强制的 `$review-feishu-background-check` 仅是成品格式门槛，不会自动升级为证据审计。仅仅存在或提供一个旧 schema payload 不会自动升级：

- 新的穷尽审计读取 `references/handoff-contract.md`；
- 兼容既有定向研究包时读取 `references/handoff-targeted-contract.md`；
- 按相应契约运行 payload、证据和成品 validator。

审计模式的失败只适用于该明确请求，不得反向成为普通背调或增量飞书写入的门槛。
