# 虚拟甲方名词质询

## 目的与顺序

模拟现实甲方第一次复查时可能出现的关注。甲方表达态度；主代理负责原帖上下文、简短事实及来源，不引导甲方放松。完整名词表服务于这个往返过程，不是逐词联网研究清单。

每次实际背调使用本技能，包括续作及对话交付；明确仅排版或同步已有结论的范围沿用原指令。技能维护不启动背调 Goal。

完成调查及必要画像补查 → 整理完整名词表 → 甲方首轮表态 → 主代理事实说明及必要复评 → 按态度成稿 → 最新成品终审 → 提交。无需在质询前先写完并终审成品；同一甲方最多五轮，不因修稿重新启动。

## 角色和输入隔离

- 本任务新建一个 `fork_turns="none"` 甲方子代理，区别于主代理及已接触调查缓存的任何代理。禁止另设前置名词查询代理。
- 甲方模拟中国游戏公司鹰角网络的运营人员：熟悉日常品牌与社区运营，关注合作内容被复查后引发争议的后果；使用符合岗位的有限常识和当前适用业务风险表。允许不认识名称，不要求理解世界各地所有议题或名词的全部内涵。
- 首轮任务材料仅为完整名词表 `[{id,name}]`，保留原词和已知别名；不能只交风险词。角色、本规程和当前完整风险表另外提供，不附调查背景、原帖、结论或预期态度。
- 固定风险表按原文完整传入，包含表内具体名称及定义，不能把这些条文改当对象背景而延后。首轮“仅名词表”的限制针对本次调查材料，不用于删减固定判定基准。
- 甲方禁止联网、读取工作目录／研究缓存／旧报告或另派代理。保存真实创建、输入、返回定位，按工具实际可见范围核对活动；不可见的活动不能自称已审计，不要求工具未提供的轨迹或消息 UUID。

## 三态及唯一输出

- **放松**：依据角色现有知识，对该名词没有产生需要追问的顾虑。
- **疑问**：不认识、存在歧义，或缺少形成态度所需的信息。
- **警惕**：依据岗位职责、已有知识和适用业务风险表产生顾虑。

首轮一次返回完整名词表的态度，原顺序、每个 ID 一次；后续只返回本轮实际收到事实说明的名词，不重复整表。格式仅为 `[{"id":"N01","态度":"疑问"}]`，不附分析、置信度或合作结论。

## 简短事实说明

主代理对首次疑问／警惕以及被拒绝答复的项目，回到对应原帖核对上下文；已核实的完整缓存可复用，不必重新联网。稳定且有把握的含义直接用通用知识说明，只有真正不确定、且影响说明的事实才针对性核实；不为每词例行搜索。

每项仅保留六字段：

```json
{"被问词":"表内原名","出现链接":["原帖完整URL"],"出现原文":["能说明问题的必要原文片段"],"上下文":["实际前后文、时间和发言归属"],"释义词所指代的对象":"简短说明实际对象","实际含义":"简短事实释义；不确定处写明具体未知"}
```

三个数组对应本次解释所需的原帖片段，不要求复制每次出现的整篇正文。不得裁掉会改变含义的条件；同义、同语境复用说明，不同所指或行为分别解释。主代理核对所有关联原帖，但发给甲方的是必要信息。背景来源有实际使用时注明；通用知识释义不编造搜索或引用。

主代理只提供事实，不夹带风险性质、品德、合法性判断或防御性说辞，不指示甲方放松。来源中的评价保留归属。甲方收到违规答复，对该项只返回 `{"id":"N01","拒绝":"包含不合规的表述，拒绝接受"}`；主代理改写后交回同一甲方，不代填态度。

## 增量复评与停止

一轮为甲方的一次实际态度响应。首轮有疑问／警惕时，必须提供简短事实并至少复评一次。后续只处理仍需澄清、有新事实或答复被拒绝的项，已解释且没有新事实时不重复发送相同答案。未再询问的项保留上次态度。

默认最多五轮，不能换代理、拆表或重置历史。只有当前用户明确授权的特定补漏例外可以追加：限定同一代理、原始全部历史、指定漏词和实际授权轮数；不得把一次例外变成其他任务的授权。复评仍警惕可以直接按必记规则收录；仍疑问且没有可补信息时保留内部记录，不进入终稿，不以说服甲方放松为目标。最后一轮不再制造一份无人复评的终止答复。最后仍有未解决的固定拒绝时不能提交；未解释过的疑问／警惕也不能跳过首次事实复评。

## 已核实事实与终稿边界

按用户 2026-11-17 最新要求：**无法确认闭环的疑问点不得进入终稿。** 不新增“待确认”“尚未完成”“待补查”等模块或说明，也不能只删状态词后把同一疑问伪装成已核实事实。已知事实、具体未知、来源和真实态度留在本任务内部记录。

**这是终稿收录规则，不是“所有疑问必须解决”的任务完成条件。** 已完成约定调查、原帖核对和必要事实复评，仍无法确认且没有可补信息的疑问，按内部记录结项后继续成稿、终审和交付。不得仅因这些疑问仍存在而判定任务未完成或 BLOCKED，也不得为清零疑问无限补查、追加质询轮次或重复终审。真实漏读、漏查、遗漏必要首次复评等执行缺口仍须补齐，不能借内部归档跳过。

`终稿必记集合 = 已完成事实核验的曾警惕事项 − 未闭环疑问 − 用户明确要求删除的事项`。

- 已完成事实核验的曾警惕事项，后续态度放松本身不撤销收录；对应原帖在标准风险摘要、平台事实和来源中有公开位置。
- 最终仍疑问，或事实归属、含义及关键关系仍未核实的事项，只作内部记录；即使此前曾警惕，也不得用该态度替代事实闭环。
- 从未警惕且最终放松，本环节不新增风险项；已有独立、已核实的调查事实按适用业务规则处理。
- 用户明确审定的删除优先于旧必记列表。保留真实授权原文、消息定位及被删事项的原始位置，不改写历史态度，不用旧门禁恢复已删除内容。
- 同帖、别名和同一事实可以共用标准正文及来源；事实措辞保持行为、来源和归属，不编造人物属性。
- 终稿仅采用既有标准格式；不增加质询过程、内部记录、释义附录、未知清单或其他自创模块。

## 记录、终审与提交

普通模式只保留同一任务内的名词／来源、真实代理消息定位、逐轮实际输入输出和最终公开位置；不用前置查询回执、逐轮哈希、重复台账或初次成品终审证明。记录使用[轻量 v3 契约](references/review-contract.md)。

成稿后调用 `$review-feishu-background-check`，再运行 `scripts/client_challenge_gate.py` 核对当前最终审阅、首轮全词覆盖、后续应答、拒绝处理、已闭环必记事项的公开位置、未闭环疑问的内部去向和用户审定删改。机器不代替语义阅读或真实代理活动核验。

旧 v1/v2 质询记录仅可显式历史回放，不能直接作为当前提交许可。已采集材料、实际语义记录和名词表可复用；不伪造新质询，也不因技能更新自动恢复用户暂停的任务。
