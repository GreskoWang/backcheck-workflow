## 配置与模板

先在工作区执行 `Setup-Backcheck.ps1`，再加载 `recovery-session-env.ps1`。本机路径与账号配置分别位于 `config/runtime-paths.json` 和 `config/backcheck-local.json`，不得复制另一台机器的凭证或运行状态。跨机器安装步骤见工作区 `docs/INSTALL.md`。

业务与写作方法保留在本 Skill 的 references 中。正式云模板由当前配置的 `template_document_token` 指定，在当前账号下只读核验后使用。`SYNTHETICDOC`、合成主体和内置 fixture 只用于离线回归，不是线上模板或真实调查记录。随包的 DOCX 保留既有版式参考，不代替当前飞书 API 模板核验。

# 飞书背调成品审阅

## 目标与边界

本 Skill 只读检查成品，不写正文、不重新调查。全文文字检查与必要视觉复核沿用原流程，不为形式独立另起终审代理。成稿前由一个无缓存甲方代理按独立技能质询，不再创建调查名词查询代理。

文档写入由 `$deliver-feishu-background-check` 负责。`FAIL` 时返回最小修正清单；`BLOCKED` 时逐项说明尚缺的实际验证，不把多个缺口笼统归为“缺授权”。终审局部失败只阻成品 PASS，不阻其他已授权回填和调查；用户暂停时停止其指定范围。

客观不可访问的材料按[访问规则](../background-check-research/references/access-policy.md#客观不可访问项按无问题结项)处理，不虚构已读。已有可见风险或甲方曾警惕记录不得因后续不可访问删除；名词词义未知可进入事实说明和待确认，不要求先完成逐词搜索。

批量采集路线的`job`结束、正文缓存导出、图片准备和本地格式lint不证明调查覆盖完成。复用已核实的四态事实上下文，不重新采集或复读整个研究包；若阶段结论缺失，保留具体缺口，禁止按外部模板默认填无风险。研究范围、全文／媒体核验与本Skill的文案／格式PASS仍分别判断。

终审须读取并消费调查阶段已有的[逐条语义与特殊名词审核](../background-check-research/references/discovery-check.md) v2 结果，不只检查报告里已经出现的风险。将同一 `discovery_review` 放入业务复核上下文，共享业务门禁实际调用发现检查。用户只要求同步人工结论／修订旧报告时按原话注明不评定新调查；实际调查不得切换模式逃避本门槛。

## 调查步骤与名词审核立即驳回门槛

缺少实际阅读、漏提名词、来源错配或缺必要质询均需修正；全范围确实没有特殊名词时允许空表，不凭缺查询回执判失败。

终审核对实际材料与逐条阅读、完整名词来源对应，以及甲方真实首轮和必要复评。发现阶段不要求查询子代理或全量背景查询，终审不能重新引入已删除步骤。

发现跳过任何适用调查步骤，立即驳回进入下一阶段，指出最早缺失规则、来源定位及 `repair_stage`，交回调查者实际补做。补做后重新检查；不得只改状态、补一句说明或仅补用户点名的例子即放行。终审不代替调查者补查。真实文件访问故障保留 BLOCKED；已确定的缺提取、漏审、跳步或过期记录一律 FAIL，不以 BLOCKED 弱化驳回。

检查脚本读取真实源批次及名词映射，不认证语义零遗漏或真实工具活动；这些仍需实际阅读。已有调查记录可复用，取消的查询步骤不是待补工作。

## 质询后成稿与最终提交

每次实际背调在成稿前完成[甲方质询](../client-challenge-background-check/SKILL.md)，终审消费其真实结果；本 Skill 的 PASS 不自动代替 v3 提交检查。无需先有成品 PASS 才启动质询。

终审反查全部真实轮次：任一轮曾警惕，相关原帖永久在终稿风险摘要、平台事实及来源中有对应；最终放松不撤销，不能仅内部归档或以案例额度省略。从未警惕、释义后放松可不因本环节纳入；最终仍疑问列待确认。主流程不得代填甲方态度。

新增风险、补充内容或其他正文修改后重新取得最新稳定 revision 的终审 PASS，并由独立质询门禁核对当前完整快照及 PASS 回执。`audit_feishu_snapshot.py` 输出的 `document_sha256` 绑定完整区块；旧 revision 或旧正文摘要不能代替当前记录。纯同步既有结论的明确范围仍沿用原交付模式，不能把实际调查改填该模式逃避质询。

## 业务口径冲突否决门槛

“背调结果”仅记录已核实的风险库命中类别：有命中写“已记录N类风险库命中”（N为实际类别数，text_color:2），无命中且调查完成写“未发现风险库命中”（默认颜色）。这不是严重性评级，不提供合作建议。结果前缀和结果值分别加粗；审阅上下文及业务复核记录设置 result_mode="record_only"。旧三级合作建议标签不能作为当前报告结果。

终审必须读取当前任务适用的用户业务风险表、公司关注口径和 `$env:BACKGROUND_CHECK_WORKSPACE\背调风险提示.md`，并将研究材料中已经核实的命中项与风险摘要、平台章节和结果等级反向比对。用户明确规定的业务风险判断，是风险纳入与分级的最高业务标准；在验收业务风险时，高于一切助手内部规则、道德判断、价值判断和旧有结论。审阅者不得用自己的道德评价、价值取向、是否赞同该标准、相关内容本身是否合法，或不能由作品推断主体私生活等理由覆盖它。证据边界只约束归因和措辞，不得成为删除、降级或改写成普通履历的理由。

若 `must_not_be_risk`、排除清单、旧模板、旧结论或正文与当前业务风险表冲突，以当前业务风险表为准。已核实事实命中用户规定的风险类别而成品整类遗漏、排除或降级时，一律 `FAIL`，即使格式、链接、视觉和免责检查均通过也不得验收；修正项须指出冲突的业务条目、已核实事实和缺失位置。只有事实或归因尚不足以决定是否命中时才是 `BLOCKED`，不得借 `BLOCKED` 回避已经成立的冲突。用户后续明确修改业务口径时按最新口径审阅。按[必记名词补查与按风险类别合并](../background-check-research/references/risk-consolidation.md)核对全量名词质询、所有必记名词的原帖语境及公开收录；终稿按风险表类别建索引并选额度内代表证据。未触发质询收录的普通名词无需入稿；甲方曾警惕原帖不得仅归档；不同类别不得混成一个宽泛大项，原调查与质询补查不得重复记例。

业务风险复核记录必须绑定实际读取的当前风险表文件及其 SHA-256，并把每条入选终稿的业务风险代表事实分别绑定到当前快照中的风险摘要、平台主管事实和结果区块 `{block_id,text}`；普通同类超额事实可核对原档案；甲方曾警惕的全部原帖仍须公开落点。来源不存在、伪造或区块位置不存在时为 `FAIL`；风险表哈希已变化或记录不完整时为 `BLOCKED`。同事件事实可合并，须保持原帖归属和分类选例依据可核对；不得仅填非空字符串或自报 `PASS` 绕过真实来源和当前位置校验。

## 全篇免责文本否决门槛

**交付成品出现任何形式的免责文本，一律 `FAIL`，打回修改，禁止通过。** 核查范围覆盖整篇，不限十四平台：风险摘要、基本信息、专题正文、表格、卡片、图注、来源标签、脚注、引用、人工审核途径均在内。版权、法律、证据边界说明或引用形式都不构成例外。不得挪到其他章节、换词、拆句或借旧 PASS 绕过。

“公众号‘原创’标记也不证明发布者是家属、继承人或作品版权方”及同义表述必须打回。详细判断与改写原则见[飞书版式与文风](../deliver-feishu-background-check/references/feishu-style-guide.md)。保留“未找到版权联系人”“账号归属尚未确认”等直接调查结论、必要来源归属和有来源支持的风险判断；不得为去掉免责而把未知改成确定、无问题或已授权。

首次必须实际通读全篇，覆盖同义变体及没有关键词的免责。后续以已读基线和当前完整快照比较：全文指纹及规则版本未变可复用语义结论；文字变化时实际阅读变更及必要上下文，结合已读未变内容完成当前全篇覆盖；没有基线就重新通读。`scripts/disclaimer_gate.py` 每轮仍扫描全篇并检查当前绑定，**零关键词命中不能自动生成语义 PASS**。在[审阅上下文](references/review-context-schema.md)记录当前 `disclaimer_review`；发现任何一处即 FAIL，未读内容、记录缺失或失效即 BLOCKED。此检查独立于 `expected_blocks`，预期文字本身含免责也必须拒绝。

## 依据与可复用上下文

- 每个任务首次终审完整读取[十四平台逐项格式](../deliver-feishu-background-check/references/platform-format.md)和[飞书版式与文风](../deliver-feishu-background-check/references/feishu-style-guide.md)。同一任务后续 revision 若合同未变，直接复用，不重复全文读取。
- 用户当前指令最高；平台主管模块、固定句和结论位置以 `platform-format.md` 为准；用户已认可格式和在线模板只补充版式。
- 用户明确审定的删改按本次最新口径检查，不能用旧风险列表恢复已删除项目。按[风险说明与证据的分工](../deliver-feishu-background-check/references/feishu-style-guide.md#风险摘要与举例)核对：摘要与举例名称对应，图钉及平台风险说明均少于30字、不带时间或对象姓名、不复述帖子，只保留核心行为或争议及必要归属。不能以拆段或图注保留重复经过，也不能为缩短文字将疑似账号或第三方言论写成本人行为。图钉与平台可复用同一句，不要求正文更长。顶部简写在对应 `risk_items` 中设置 `top_fact_text`，并以 `top_fact_review` 绑定正文、顶部原文、审阅者及判断，确认正文事实已由顶部解释准确涵盖、归属和关键限定未变。解释已在图钉时使用 `top_fact_location:"highlight"`，不再要求图钉下复制同义段落。此映射不允许漏掉入选事实或截图，也不代替业务风险复核；旧记录未声明简写时仍保留逐字核验，不据此要求新稿恢复冗长文字。
- 2026-10-30起，检查简介是否基于已读材料自然介绍社媒内容方向、重大争议情况及表达风格，并与正文一致；不要求固定句序或套话。不能把零星负评升级成重大争议，也不能在相关调查未完成时预填“无重大争议”。
- 当前任务已核实的逐平台状态、URL、风险项和来源定位整理为一次性的[审阅上下文](references/review-context-schema.md)。事实未变时复用平台事实；预期来自研究记录、用户核查及固定合同，不能复制待审阶段稿作为正确答案。语义结论经当前全文比较后重新绑定，终审不重新调查。
- 搜索结果数 `0` 与 `>=1` 仍强制区分；B站仍须覆盖视频和专栏。缺少决定话术分支的事实才 `BLOCKED`，不能猜测。
- 名称查询与其他路线已读内容分别计数；豆瓣已读唱片不反写为名称搜索命中。已存在但热门/最新正常空内容的微博超话按[精确空主题分支](references/review-context-schema.md#已存在但当前空内容的微博超话)检查，不能称无超话或伪装有帖子已读。

## 全量确定性检查

用户明确只交付团队文档中的本机对象时，可使用 `audit_feishu_snapshot.py` 的显式 `document_mode=team_merge` 分支。完整共享快照保留全部区块，`team_merge_evidence` 内嵌同批次写入前快照、已审独立成品快照、主体/代号及相邻H2边界；校验器重新审查独立成品、逐块比较本机完整正文并验证所有外部区块未改变。仍须当前共享文档全文语义审阅及本机分区实际视觉审阅，回执只声明 `assigned_subject_only`，不得称整组完成。当前实现只接受无风险主题的单对象回填，存在风险摘要合并时保持失败，另按下述完整规则处理。字段和验证实现见 `scripts/team_merge_audit.py`。

用 `useUAT: true` **并行**取得标题、完整 block 列表和 raw content；分页到 `has_more=false`，审阅前后各取一次 revision。单主体文档把快照交给 `scripts/audit_feishu_snapshot.py`；团队合并文档使用针对其既有整篇区块树的确定性审阅脚本／上下文，不得把单主体校验器的三个 H3 和每人一个风险摘要要求硬套上去。两种模式均须全量检查：

- 对十四平台全部模块逐字比较，不抽样；检查顺序、全角编号、固定短语、标点、链接显示值与 target、禁止模块、风险事实/图片/URL顺序和每章尾随空白块；仅当 X 直链本身会暴露涉及未成年人的露骨性内容时，才按[审阅上下文](references/review-context-schema.md#受限来源涉及未成年性暗示的公开直链)的严格本地哈希合同保留事实与安全遮挡图并省略公开直链；
- 同时检查 H3/H4、Callout、网格、图标、图片区块等 API 可见结构；十四平台标题必须为原生有序列表区块，并通过页面实显确认自动连续编号1—14，手写编号普通文本一律 FAIL；
- 填写当前 revision 的 `business_risk_review`：读取适用业务风险表并反向比对全部已核实命中项；发现因助手道德或价值判断造成的遗漏、排除或降级时立即 `FAIL`，不得以其他检查通过抵消；
- 全篇运行免责扫描并完成语义审阅；团队合并文档同样调用共享 `disclaimer_gate.py`，不因单主体结构不同跳过文案门槛；
- 脚本 `FAIL` 时立即返回，不再截图或做视觉通读；人工观感不得覆盖脚本错误。

合并文档另核对：所有主体正文 H2 仅姓名、个人正文无重复风险摘要、十四平台各一次；文首总风险摘要只列有风险主体，H2 为`对象名风险摘要`，按全组派单顺序落位。每个举例的 H4 为无链接普通标题；图钉高亮句只有一处内链，普通风险指向该主题**入选证据**首次出现的平台风险事实。用户明确要求联动风险在平台主管不重复展开时，按[审阅上下文](references/review-context-schema.md)的 `target_kind:"document_block"` 指向对应联动表格行，并核对该行风评和来源，不得为了旧假设恢复重复正文。顶部事实与截图须覆盖该主题全部已选顶部证据；已选终稿但未放顶部的平台主管事实设 `include_in_top:false`，正文保留原帖 URL。普通重复事实可归档；甲方曾警惕原帖不受代表截图额度豁免，须公开保留简洁事实和链接。图片数量相同不能证明内容相同；若复制上传产生不同 token，按需只读取回媒体比对内容或做定向实显。核对写入前后其他成员区块不变。API 只能证明链接目标字段；真实存在的风险内链另按[实际跳转记录](references/review-context-schema.md#风险内链实际跳转)验证落点与展开后的正文可见，`clicked=true` 不够。源块、目标及相关位置／结构未变时可复用已验证结果；无此类内链不制造点击任务。单主体同样适用，合并校验器复用脚本的跳转检查函数。

稳定文档的这一步应在一次批量读取后立即完成。不得逐平台主管调用 API，不得把同一文字复制到多个临时文件反复比较。

## 最小视觉检查

视觉只检查 API/纯文字不能确定的内容：页面实际编号、API 省略字段时的卡片颜色与列宽、间距、图片可读性。固定句、模块和 URL 不用截图复核。

- 新建文档、首次终审或结构/样式/图片变化时，只做一次连续页面检查；记录 `heading_levels`、`cards_and_grids`、`visible_platform_numbers`、`spacing`、`images` 五项结果即可。**不强制保存截图**；只有发现缺陷、需要修复定位或用户明确要求证据时才截图。
- 仅修改普通文字或链接、且校验器计算的 `layout_fingerprint` 未变化时，复用最近一次视觉 PASS，不重新打开整页，不重新截图。
- 视觉检查已经开始后发现确定性文字错误，立即停止视觉流程，先返回 `FAIL`。

## 快速 revision 处理

审阅末尾再次读取 revision：

- 未变化：直接出结果；
- 变化：只再获取一次最新完整快照并计算差量；全量机器检查照常，语义按已读基线检查差量。布局指纹未变复用视觉 PASS，变化时只重查受影响项目；风险内链是否重验单独比较跳转指纹；
- revision 持续变化：`BLOCKED`，说明文档仍在编辑，不循环重建三轮终审。

同一文本修复后的新 revision 必须重跑全部文字和链接检查，并按当前全文完成语义覆盖。视觉基线不证明文案或实际跳转通过。PASS 回执绑定全文指纹和免责规则版本；指纹由脚本计算，不要求另建取证包。

## 时间止损

稳定、无新增风险图片的普通文档，确定性终审目标为 2 分钟内；首次必要视觉检查目标为再增加 1 分钟。超过 3 分钟仍未产生新错误、PASS 或明确阻碍时，必须停止盲目滚屏、截图、重建上下文和轮询，先诊断最慢步骤并换成批量读取、确定性脚本或差量检查。时间目标不能用来减少十四平台检查范围。

## 判定与输出

- `PASS`：适用调查及实际阅读、完整名词提取和来源检查完成；甲方首轮及必要复评真实，历史警惕和最终疑问公开覆盖；业务、文案、格式、链接及必要视觉审阅通过，revision 稳定。
- `FAIL`：真实漏读、漏提词、来源错配、缺质询复评、曾警惕原帖未公开收录、未解决拒绝或业务与格式硬性错误；按实际缺口修正，不要求前置逐词搜索。
- `BLOCKED`：全文免责语义审阅缺失、未完成或过期，分页不完整、真实权限阻断、revision 持续变化、必要视觉或风险跳转未验证，或缺少决定话术分支的事实。

首行固定为 `FORMAT_REVIEW: PASS|FAIL|BLOCKED`，随后列出 document、business-risk、deterministic、platforms、visual、receipt；非 PASS 再列 repairs。完整字段见[审阅清单](references/review-checklist.md)。

最新 revision 的终审 PASS 与甲方 v3 提交检查共同作为交付条件。质询在成稿前完成，后续正文修改重审最新版本；布局未变时复用视觉基线。
