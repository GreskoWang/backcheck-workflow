## 配置与模板

先在工作区执行 `Setup-Backcheck.ps1`，再加载 `recovery-session-env.ps1`。本机路径与账号配置分别位于 `config/runtime-paths.json` 和 `config/backcheck-local.json`，不得复制另一台机器的凭证或运行状态。跨机器安装步骤见工作区 `docs/INSTALL.md`。

业务与写作方法保留在本 Skill 的 references 中。正式云模板由当前配置的 `template_document_token` 指定，在当前账号下只读核验后使用。`SYNTHETICDOC`、合成主体和内置 fixture 只用于离线回归，不是线上模板或真实调查记录。随包的 DOCX 保留既有版式参考，不代替当前飞书 API 模板核验。

# 公开来源背调

## 目标

通过主体自己的公开发言、转发、配图、视频与互动，以及玩家和社区对主体的公开讨论，发现可能牵连合作公司品牌声誉的内容。

背调负责**发现和记录公开风险，并给出三级评估结果**。由执行调查的助手依据已核实事实，按[背调结果分级](references/methods.md#背调结果分级)填写“建议谨慎评估／建议评估／低合作风险”，不要求用户或上游先提供结论；不评价主体品德，也不代替需求方作最终合作决定。默认按普通人工业务背调执行，效率和风险发现优先；普通单人任务按三小时内形成可交付结果来调度。这个时间目标要求及时换工具、隔离故障和增量交付，不能用来跳过确认或纳入主页的公开文字帖子与配图。

## 业务风险口径优先

在风险识别、分类、记录和交付中，用户明确提供的业务风险表、公司关注口径，以及 `$env:BACKGROUND_CHECK_WORKSPACE\背调风险提示.md` 中标明“均算风险”“所有相关内容都算”“公司关注口径”或其他必记含义的条目，是本任务的最高业务判定标准；在业务风险判定上，高于一切助手内部规则、道德判断、价值判断和旧有结论。不得以助手个人的道德评价、价值取向、是否赞同该口径、相关内容本身是否合法，或不能由作品推断主体私生活为由，把已经核实命中的业务风险排除、降级为普通履历，或从风险摘要和平台章节删除。

证据与归因边界只限制成品能写到什么程度，不改变用户已经规定的业务分类。例如，可如实记录主体参演、制作或公开表达参与同性题材作品的事实及其合作风险，但不得由此推断主体的性取向。事实不清时继续核验或保留具体缺口；事实已清且命中必记口径时必须记录。

任何临时排除表、`must_not_be_risk`、旧报告、旧模板或历史结论与当前业务风险表冲突时，当前业务风险表优先，冲突排除项立即失效。只有用户后续明确修改业务口径，才允许排除或降级。交付前反向比对全部已核实命中项与风险摘要、平台章节和结果等级；若因助手自己的道德判断造成遗漏、排除或降级，调查视为未完成，必须修正并重新终审。

调查时间窗按原需求的**每个需求块／对象**分别确定：只有该块或该对象明确写了“更新一年”“一年”等一年限定，才以其需求日期为基准核查最近一年；同批其他未标明一年限定的对象仍按正常公开可见范围查看。不得把一个块的时间窗扩展给另一块，也不得因派单批次名称或旧报告默认截断未限定对象。用户另有明确起止日期时按该日期执行。

## 首先启动 Goal

用户于2026-09-12明确授权：每次提出新的背调执行要求，默认自动开启 Goal，不再要求用户输入 `/goal` 或另行确认。此授权适用于实际背调及其续查；询问方法、解释进度、修改 Skill、单独同步已有结论不另建背调 Goal。用户明确取消、暂停或限定范围时服从该指令。

1. 先调用 `get_goal`。没有未完成 Goal 时调用 `create_goal`；已有本任务 Goal 时沿用，不能重复创建。存在其他未完成 Goal 时保留其目标，不覆盖或谎报完成来腾出位置。用户暂停的 Goal 不擅自恢复。
2. 创建目标时写入主体、用户指定账号、实际调查范围、最终交付位置及可核验完成条件。默认完成条件为：按本 Skill 完成纳入主页和十四平台调查，形成并审阅飞书成品；随后完成至少一个基于检索画像的补充二查方向，若发现遗漏则补入飞书并重新审阅；所有结论与实际证据对应。用户缩小范围时同步缩小条件；没有用户指定的 token 预算就不设置 `token_budget`。
3. `create_goal` 返回成功后再开始调查，并通过 `get_goal` 核对目标真实存在。调用失败先读取实际状态，不能只凭回复“已开启”或本地待办代替 Goal，也不盲目重复创建。工具缺失或失败时继续可执行工作，并准确说明 Goal 未启用，不让用户补发“继续”。
4. 只在全部约定工作实际完成、交付核对通过后调用 `update_goal(status="complete")`。发现风险、写入阶段稿、完成单个平台、时间目标到期、剩余预算减少或准备结束回复均不构成完成。`blocked` 仅按工具规定，在同一真实阻碍连续至少三个 Goal 回合且已无其他可推进工作时使用；否则保持目标有效并推进。

## 调查闭环完成即汇报

用户于2026-10-14明确要求：**每次完成一项调查闭环，必须立即在当前 Codex 对话通过 commentary 汇报一次**，不等待用户询问、所有平台完成或整份报告交付。闭环包括一个纳入主页、一条平台名称搜索路线、一组定向补查、一个具体风险线索核验，或一个平台整体达到本 Skill 的完成标准；单次工具成功、扫到封面、写入暂存文件不单独算调查闭环。

汇报使用连续闭环编号，并简短说明“对象＋完成事项＋实际完成数量／该项总量＋实际结论＋下一项”，同时给出该对象已完成平台数／应查平台总数；多对象批次可附累计平台数／总平台数。数量只使用已核实数据，总量未知时直接写“总量未知”，不得估填；风险图核验等局部闭环不增加整个平台完成数。必要时补充已读范围或仍未完成的部分。区分“无相关结果”“有相关结果且已查未见问题”“有风险”“尚未完成”，局部闭环不得写成整个平台或整项背调完成。

多分支执行时，子代理完成消息不能代替主代理面向用户的汇报；主代理收到闭环结果并核对后立即汇报，同时完成的多项可以合并一条消息，但须逐项点明，不得遗漏或积压到阶段总结。汇报后继续下一项可执行工作，不结束原范围、不要求用户补发“继续”。飞书派单任务只在本 Codex 对话汇报，派单群静默要求保持有效。

## 方法积累与复用

用户已授权持续沉淀经验。开始平台操作前读取其规程，异常时先按[通用排障方法](references/methods.md#通用排障方法)执行已有有效办法；同一经验保留一个权威位置，不再添加重复禁令。跨平台判断写入 methods.md，平台特例写入 platform-runbook.md，认证权限写入 access-policy.md，飞书操作交给交付 Skill。只保存可复用条件、有效动作、成功判据和证据出处；账号、断点和会话ID留在任务内。

必要操作受阻、证据丢失或结论可能失真时，在既有授权内执行[致命问题修复与沉淀](references/methods.md#致命问题修复与沉淀)。区分已改代码、测试通过、运行实例生效、原场景成功；用户接管、排除内容或替代路线成功不证明原故障已修。普通调查遵守止损预算；用户明确委托专项修复时，按 web-access 的受控重载流程处理，保护 Edge 与原任务页，不以“交付前不重启”拒绝已授权修复。

## 普通背调主循环

### 1. 找账号，但不追求证明零遗漏

先检查已确认主页的简介、关于页、置顶、链接栏和聚合页，再做名称搜索。平台图标、emoji、缩写、谐音和单独列出的 handle 都是线索，结合语境识别，不按固定字典确认归属。本人链接的事务所、项目、店铺、关系人不能自动算本人账号；只沿身份明确的一跳展开。

确认依据和疑似处理见[账号处理决策](references/methods.md#账号处理决策)。明确自述本人拥有、身份与持续内容相符的主页正常查看；官网／简介直接给出的同名叶子链接是强锚点，不能机械要求反向互链。搜索首位有两项以上独立身份对应时可确认；名称相同或单纯被链接不够。

- 用户给出的主页全部处理；其他候选中，同平台最多自动选一个最接近锚点的同领域疑似主页正常查看，其余快速分类。
- 同名且同领域疑似主页不等待严格验证，交付仍标“疑似主页”；少量内容看完即停，不继续深挖身份。
- 明显不同领域的账号只说明不一致；疑似出现风险时只做一次轻量归属核对，仍不明就保留疑似风险，不能归给主体。
- 用户已人工查完并给出结论的范围直接接受；不重复调查，也不把人工接管记作工具修复。

十四个平台固定为：微博、B站、抖音、小红书、知乎、网易云音乐、贴吧、豆瓣、境内其他内容、X、Facebook、INS、油管、境外其他网站。调查可按可用性并行；飞书按固定顺序。空结果依据实际页面与各平台规程，豆瓣按其用户确认规则。

### 2. 主页从新到旧，一边看一边判断

**主号优先，一页单向推进。**确认归属与媒体范围后，在同一列表从新到旧按屏／批次读标题、正文、配文、引用附言及本人公开回复；疑点、折叠正文、未展示图集、重点视频和用户点名项才进详情，核完回原断点。正常内容直接继续，不逐帖存链接、编号、截图、“无问题”说明或模型审阅回执，不为找理论更快的工具、累计帖数差额或重复身份验证打断稳定路线。

较长主页优先用web-access的[可恢复批量缓存](../web-access/references/research-batch.md)，先核对账号、用户时间窗和最新端／既有断点，再让固定后台配方取得完整可见文字。新任务只维护一份阅读缓存，按需读取一批、实际读完后确认并推进断点，不反复导出整套正文或另写逐帖阅读账。采集等待时处理已取得正文或其他域名。来源映射由工具保留在必要缓存中；折叠、摘要、占位、未展示媒体和终点待确认保留具体缺口，不能用摘要、关键词扫描或job结束冒充全文完成。从当前页中段取得的结果不覆盖更早未读范围。

采集启动后挂接批量说明中的本地watch接续，自动准备全文批次、媒体和审阅待办；收到阶段结果就继续阅读核实，不反复询问滚动状态。详情缺口调用[固定详情客户端](../web-access/references/research-detail.md)，停止同页采集并核对来源与主体后再展开；客户端已有接口可用时，不因其他任务不能重载broker而停止适配。监听、接单、记账和分发继续由dot负责。

图片在作品列表／九宫格整屏看缩略图，无疑点即通过；只有具体疑点才放大。未展示图集只补其缩略图，重复作品跨平台复用；占位和未看画面不能计已看。公开 Instagram 精选／Stories可直接只读浏览，留下浏览记录不构成停查理由，互动权限按访问规则。

视频列表快速看标题、封面和发布信息；重点视频只选少量不重复代表项，展开简介并看足以判断语境的片段、字幕／转写及代表评论，不随频道总量增加样本。风险项和用户点名项另核。只见封面只能说封面；0:00、缓冲、评论计数、字幕按钮不能证明内容已读。批量工具仅加速取得正文，不替代全文、画面和归因判断。

暂时到底、moved=false或atEnd不是失败或历史终点。先执行[通用排障方法](references/methods.md#通用排障方法)：核对实际滚动容器，原页小幅上滚再下滚并按平台时序等待。没有新增的同一轮停滞共用3分钟预算；实际出现新正文／日期后从原处继续，正常推进不受整页3分钟限额。不得恢复前先宣布失败，也不从顶部重跑。有限恢复后正常渲染但无更早内容，记录实际可见范围；错误、占位、截断和未展开内容保留具体缺口，不写成已读或绝对历史末尾。

出现字面或语义风险信号立即按[关键词与语义信号升级核查](references/methods.md#关键词与语义信号升级核查)核对原文、语境、归因和必要媒体，再回断点。每个具体风险主题一次主查询、必要时最多一次备用查询；不能只靠精确词表排除隐喻或当地语变体，也不占用成品后的独立补查。

社媒累计数不作差额追平依据。静态博客连续文章ID的少量缺号才按[大账号与页面终点](references/methods.md#大账号与页面终点)短查；有明确残留／迁移映射才查存档。无具体风险线索不做无边界历史考古。

### 3. 每个平台搜索一次，再做少量定向扩搜

从确认来源整理最多3项实质不同别名，每个平台选最适用的一项主查询；同名污染或首批无主体结果时最多一次别名／职业／作品消歧。内容结果共用前三页或前30个唯一结果，切标签、恢复搜索和外部兜底不重置额度；用户／商品／作品目录只用于发现线索，不能代替风评内容搜索。这个额度不限制主页遍历。

搜索与主页可并行，先看已给主页平台和境内／境外其他入口的第一屏找线索，再补剩余范围，不重复同一查询。回读实际生效关键词、结果标签和内容；外语复制原词并用编码库或搜索框提交，不手拼百分号。只有URL、默认流、空DOM或框架不能支持零结果。

整个对象通常合计追加1—3组相关定向组合，优先百度、Google、当地搜索或已有信号的平台；外国对象可将其中一组用于当地风评表达。具体事件直接搜事件，不生成近义词矩阵。账号内筛选若用于补时间线，先以现存内容确认生效，一次失败即停。详情和限额见[名称搜索与定向搜索](references/methods.md#名称搜索与定向搜索)。

同一URL、账号、争议主题只归因判断一次；风险线索当场保留原URL／独有短句。找到足够来源与语境即停，主查询加一次备用仍不明则记未坐实。外部site检索只能证明当前公开索引的结果，不能冒充站内搜索完成或推出账号不存在。

### 4. 用玩家与品牌视角决定是否记录

先按当前任务适用的业务风险表和公司关注口径判断。凡其中明确写为风险、必记、`均算风险`、`所有相关内容都算` 或其他同等含义的关联事实，在对象、行为与语境核实后必须进入风险记录，不再附加“普通玩家是否明显反感”的二次过滤。只有业务风险表未明确覆盖的候选内容，才需要同时满足：

1. 它属于风险提示库关注的政治、主权、公序良俗、色情低俗、仇恨歧视、违法失德、群体冲突或其他声誉风险领域；
2. 一个没有粉丝滤镜的普通玩家看到后，可能明显反感主体，并把负面感受转移到合作公司，或使公司品牌声誉受到现实威胁。

具体尺度：

- 一次小周边迟发货且主体已正常说明、致歉或补救，通常不记录；若反复发生、影响广泛、长期不处理、存在欺骗线索或以攻击性方式回应，再记录相应现象。
- 判断擦边或色情时，普通 Cos、女性露出大腿或胸部、穿黑丝、服装贴身本身不构成风险。按用户2026-10-15澄清，结合完整画面与发布语境，看暴露是否被刻意组织成性凝视或性暗示，包括不自然或带情色指向的表情、色调、镜头角度、姿势、动作与配文；不能仅凭一个露肤部位、低角度、脸红或汗滴定性。露出程度及“是否适合孩子看”不能单独作为判据；普通审美、角色服装与一般 Cos 不按色情处理。
- 政治和社会议题按中国互联网语境判断。只要存在稳定而明显的反对阵营、很难形成广泛一致，就作为可能引发争议的公开立场如实记录；这包括部分政治立场、LGBTQ、BLM、动物保护、防疫措施等议题。记录本人公开表达、互动方式和舆情可能性，不裁决哪一方正确，也不从内容推断未公开的敏感个人属性。
- 台湾对象把中国大陆单独简称为“中国”，并在同一表达中把“台湾”并列为另一方时，按中国大陆业务语境记录为涉台主权／台独语义风险；“中国用语／台湾用语”“去中国／回台湾”等分立句式不能仅以地区差异或语言习惯解释为无风险。必须核对本人原创、回复、转发附言或引用批评等归因和完整上下文；成品引用原句并客观说明其“中国与台湾并列”的分立语义，不由单条措辞外推主体未公开的完整政治主张。
- 已核实的台独、反共或反华表达是中国企业合作准入的绝对政治红线，不适用“不同立场均可接受”“学术争议”“言论边界”等中和口径。归因和语义一旦成立，背调结果直接使用最高档“建议谨慎评估”，并在风险摘要或对应事实中明确写“触及公司不可妥协的政治红线，建议否决合作”；不得降格成“可能敏感”“可能引发争议”或仅建议一般复核。事实核验仍用于排除错人、断章取义、反串、新闻转述和批评性引用，不因此放宽证据要求。
- 只有近似不同立场均可接受、几乎不会在中国互联网形成明显反对阵营的议题，才按低争议处理。
- 第三方指控只写“社区存在何种讨论”，不能改写成主体已被证实的事实。主体原创、转发附言、本人回复、点赞或其他互动分别归因。

同一平台按风险项汇报，不穷尽同类风险点：每个平台的每个风险项最多保留4个经核实的代表例子，1—4个均可，3—4个较理想但不是配额；已有例子足以说明性质后，停止为该项继续点开、取证、截图、计数或追加案例，不为凑到3—4个继续搜索。后续扫到同类内容直接略过，继续识别其他风险类型；只有出现新的实质风险类型、严重程度明显不同的事实，或会改变既有结论的反证时才另行核实。不能把最多4个例子的额度分别重复分配给每种姿势、服装、角色、帖子形式或本人／转发；归因仍须在选用例子中分别写清。该规则适用于调查过程与飞书交付，不能只删报告篇幅而继续穷尽采集。

### 5. 只保留最小结果

交付基本信息前，对代表作候选核实本人参与，并按[飞书成品的代表作选取规则](../deliver-feishu-background-check/references/feishu-style-guide.md#基本信息)确定优先级；不要仅凭同名搜索结果或作品知名度推定参与。此处只在准备交付基本信息时读取交付规则，不改变调查开始时的最小加载范围。

整理交付文案时，遵守[全篇免责文本禁令](../deliver-feishu-background-check/references/feishu-style-guide.md#文风)：任何免责说明、证据边界套话及变体一律 `FAIL`；保留直接调查结论和必要来源归属，不把未核实内容改写为“无问题”。

平台完成后，只保留平台入口、实际搜索链接、已查范围和结论，风险项另留必要证据。每个任务维护一份权威的当前结论与剩余项，已有 `current-state.json` 等任务状态时直接增量更新，不再平行维护同内容的调查结论、交接摘要、逐批模型审阅回执。工具的阅读游标由工具维护，业务状态只引用其路径与剩余动作，不手抄逐帖映射。没有既有状态且飞书暂时不可写、需要交接或可能中断时，可使用：

`$env:BACKGROUND_CHECK_WORKSPACE\YYYY-MM-DD\<对象>\调查结论.md`

当前状态保留基本信息、飞书文档链接、逐平台结果，以及未完成项的下一步。最小断点包括范围、可定位的最后帖子／页面位置、正文和媒体各自的进度、具体缺口与已用恢复次数；哈希仅辅助去重和变更核对，不能代替位置与完成状态。没有变化不重复落盘，不因每张图或每次滚动另建文件。每个平台记录以下四种实际状态之一：无相关结果、有相关结果且已查未见问题、有风险、尚未完成。已完成且未见问题的平台记录：

- 有主页时记录主页 URL 和实际名称搜索 URL；无主页时记录“无主页”和实际名称搜索 URL；
- `无问题`。

疑似主页同时标明“疑似主页”；领域不一致时增加一句内容概括。风险项只记录：

1. 一句客观事实；
2. 一张或少量必要截图；
3. 原帖或原内容完整 URL；
4. 必要的归因标签，例如“本人原创”“本人转发”“本人点赞”“第三方讨论”。

阅读缓存用于完成正在进行的阅读与恢复，不作为无问题材料的永久逐帖档案。平台闭环且交付核对后，由原任务在确认无未读缺口、无待用媒体、风险证据已独立保留时回收其临时缓存；不得由维护任务清空共享目录或现存旧断点。旧任务沿用原阅读格式和已确认记录，不为采用精简格式重采、重读或重置恢复次数。

已确认主页中的正常内容，不因缺少每帖直链而逐一补链接或另建待办；只有风险归因、具体疑点或恢复定位需要时再补。正文截断、未展示图片、范围缺口和账号不明仍须处理，不能借精简记录跳过实际阅读或确认。

截图只保留**账号名或头像等归属信息、帖子文字或图片主体、以及证明转发／点赞关系所需的界面**。裁掉浏览器标签栏、地址栏、书签栏、系统任务栏、通知、其他页签和无关页面内容。上传前再次检查；如仍含无关私人信息，先裁切或局部遮挡，但不得遮住风险事实和归属信息。

按[调查闭环完成即汇报](#调查闭环完成即汇报)立即向用户汇报，并继续下一项可执行工作；该平台达到可写状态后交给飞书交付 Skill 增量回填，飞书不可写时再更新暂存文件。不要等待十四个平台全部完成才回填，也不要把增量回填当成结束原始调查的理由。

### 6. 飞书成品后做一次检索画像补查

十四平台常规调查完成、结论写入飞书并通过第一次成品审阅后，主动提出一个具体易漏问题，不等待用户追问。按[检索画像与补充二查](references/methods.md#飞书成品后的检索画像与补充二查)，结合已确认的国别、语言、职业、作品、合作对象和平台选题；画像仅用于检索，不推断未公开属性。候选词参考风险提示库，不逐词穷举。

通常一个子题，确有独立遗漏风险最多三个；每个子题一次主查询、必要时最多一次备用，人工核对前三页／前30个唯一结果或真实终点。不得原样重放首轮查询或以一题零命中代替其他题。当前任务保留具体问题、实际查询、已读范围和“出现对应内容／未出现对应内容／尚未完成”。命中补入对应平台并重新审阅，未命中不把过程写入成品；至少完成一个问题后才能结束整项任务／Goal。

## 持续执行与交付条件

每次汇报后按下面条件直接决定下一动作，不能用阶段稿、已耗时或回复长度决定停工：

| 当前事实 | 下一步 |
| --- | --- |
| 主号或其他平台仍可读 | 从现有断点继续，先主号与必需范围，不被零星失败和侧线拖住 |
| 列表停滞／占位／控件失配 | 先做已验证的原页恢复、重新定位，再判断；不要索要本可自行定位的帖子链接 |
| 登录或验证需要用户 | 保留一个待处理页并提出一次具体需求；只挂该路线，继续其他平台和飞书 |
| 控制器或截图失败但正文仍可读 | 只隔离失败能力，继续文字／其他获准路线；不把工具错误归为站点不存在 |
| 飞书授权过期 | 交付Skill处理既有授权续期；其余研究继续，不把过期本身当作需用户回复 |
| 用户反证先前结论 | 撤回失去依据的句子、核对原页及同类错误，随后从断点继续 |

恢复时读取原范围、已完成项和具体剩余项，直接执行一个可行步骤，不重新写计划后结束。进度询问、规则维护、同步成果和上下文压缩不取消原范围；用户明确停止、暂停或变更范围时服从。工具Goal状态与用户续作授权不同步时如实说明，不伪造状态；无resume接口不阻止其他已授权工作，也不擅自恢复用户暂停的目标。

文字获取、正文阅读、配图、重点视频／互动和搜索按实际完成程度区分；列表文字全读不等于媒体全看，评论数量不是评论正文。四种平台状态保持一致：无相关结果、有相关结果且已查未见问题、有风险、尚未完成。用户排除或人工接管单独记处理结果，不作技术修复证据；不要新增台账或研究包。

准备final或完成Goal前核对原始范围、具体剩余项和交付回读。有可执行项就继续；只有全部剩余项确实依赖外部条件时，保存每项阻碍、已试动作和恢复入口，如实说明未完成并遵守Goal的阻塞条件。没有成功设置工具就不能宣称后台续作、定时唤醒或自动重试。

## 工具与止损

- 浏览器、认证、并发、截图和重试以[访问与工具规则](references/access-policy.md)及web-access为权威位置；不重复定义底层API。使用持久登录态Edge，不以内置／临时浏览器替代。
- 一页一个owner，同一注册域名同一时刻一条请求路线；通常复用1—3个任务页，主动占用不超过5。页满先回收本任务已完成页／租约，不碰用户无关页，不为单图或重试新建代理。
- 同一轮页面／控制故障正常尝试加一次恢复，共用3分钟；同组件同错误的脚本调试全任务共用10分钟。只有条件或状态实质变化才重试；取得新内容后正常阅读继续，不误把止损预算当整个平台时限。
- 明确验证码／限流只冻结对应站点路线；控制通道失效不在十四个平台重复试。同类失效截图不能阻正文阅读或其他平台。
- 使用已登记的公开API、获授权导出和工具加速，工具存在／命令成功不证明完成；新工具先短时只读试验，具体禁用入口不扩大成对全部控制技术的禁令。
- 已授权的专项修复先做回归再受控切换，确认运行实例和原场景；普通调查不因维护重启Edge／broker，保留任务页与连接。

## 平台完成标准

一个平台完成，指：

1. 该平台的确认主页和本次实际选入的疑似主页已按规则处理；其余同名候选已快速分类；
2. 需要完整查看的主页全部公开可见文字帖和配图已按第 2 节的单向流程看到本次可见终点；用户明确排除的媒体不列为未完成；加载错误、空白或未读占位仍是具体缺口；
3. 用户未排除视频时，视频列表已快速扫读，重点视频的简介、内容和代表性评论风向已处理；
4. 主体名称或账号名搜索的前三页或前 30 个结果已看；
5. 该平台发现的风险已记录事实、隐私裁切截图和原帖 URL。

整项调查在上述平台完成条件之外，还必须先形成并审阅飞书成品，再完成至少一个检索画像补查方向。补查在当前任务状态中保留选择理由、实际生效查询、人工查看范围及“出现对应内容／未出现对应内容／尚未完成”之一；发现成品遗漏时补写并重新审阅飞书。

某个平台受阻只影响该平台。其他平台继续完成和交付；不得因单点失败撤销已完成结论，也不得把访问失败写成“无问题”。

主页文字、用户范围内的配图／图集与重点视频、平台搜索分别核对是否完成。文字翻到终点不代表纳入范围的配图看完；实际看过且足够清晰、无疑点的缩略图可以完成对应图片筛查，不能仅因未打开原图就列为待办。占位图、读取成功或页面计数不证明图片已查看。存在中间日期缺口、未展开图集或未加载图片时，保留其位置，不得用“最早看到某日”概括为连续覆盖；用户明确排除的媒体不构成缺口。搜索结果不足三页或 30 条时，以明确的结果终点为完成条件，不为凑数扩大查询；加载框架、空白和截断都不是结果终点。

## 取证级穷尽审计

只有用户明确要求“取证级”“穷尽审计”“取证包”“全部媒体／评论逐项留证”“机器校验”或点名 `exhaustive_audit` 时，才读取旧版交接契约并启用查询矩阵、逐项台账、媒体时间线、哈希、研究包和严格校验。用户要求把主页从头扫到尾仍属于普通背调，不得因此自动升级。
