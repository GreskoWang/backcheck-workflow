# 必记名词补查与按风险类别合并

本规则按用户 2026-11-11 的明确修订执行，替代“所有必记名词及每次出现均须进入交付文档”的旧口径；适用于调查、甲方质询、交付和终审。

## 必记的对象是补查责任

`补查清单 = 任一轮曾警惕的名词 ∪ 释义后最终仍疑问的名词`。历史警惕保留在清单中；后续放松不抹去补查责任。名词不要求全部出现在终稿，警惕或疑问也不直接构成风险类别或新增风险点。

调查 Skill 必须逐项回到实际原帖，核对完整语境、日期、发言者、本人附言、转发／引用／回复关系及相关媒体，补足对业务判断有影响的事实。可复用本任务已实际核实、来源一致的完整原帖缓存，无须为了“回归”再次联网打开。不能只复述词典释义、看名词字面或用模型态度代替补查。同一帖子涉及多个名词或别名时共享一份补查记录；同词出现在不同语境时分别处理。

## 原帖语境决定分类

1. 根据当前业务风险表的具体类别及条目归类，保存类别原名、对应条文和实际命中事实。分类依据是帖子中的行为与语境，不是被问词的名称或子代理态度。
2. 同类别、同一风险性质的多条帖子合并汇报；姓名、别名、账号、媒体名和同一事件参与者不得各立一个风险点。不同业务类别分别建清晰索引，不使用“社会议题及其他”等大筐吞并无关类别。
3. 同帖确实命中多个类别时可以交叉引用同一证据，不复制整段正文或截图。同类别中新的实质风险类型、明显不同的严重程度及会改变结论的反证须单独核实并明确表达；优先替换代表证据或在该类摘要说明，不能借新人物、帖子形式、原创／转发、子标题重开案例额度。
4. 核实后未命中风险表的，文字存档核查事实及依据，不为凑齐名词强塞风险正文。事实仍未知则记录具体未知，不虚构命中；真正尚未执行的补查仍须完成。已确认删除、封禁、关闭、隐私或限制查看等客观不可访问项按[访问结项规则](access-policy.md#客观不可访问项按无问题结项)记“无问题”结项，不恢复为待办；其余可见证据独立判断。

## 代表证据额度与文字归档

- 每个平台、每个风险表类别统一使用一份代表证据额度：1—4 例均可，默认推荐 3—4 例；较少例子已能说明性质时可提前收口，不凑数。当前任务明确给出推荐数量时优先遵守；内部记录选定的数量及选例理由。
- 达到选定推荐数量后，同类重复事实不再追加终稿、不再额外截图；仍须完成补查、分类和文字归档。原调查和质询补查共用额度，不能分别计数。
- 以独立原帖／事件证据计数，多个名词、别名、同帖多图及其视频或引用材料不各算一例。最终选择应有代表性、可核验、归属清楚；不能把新增多个事件塞进一个长段落伪装为“一例”。
- 文字档案保留名词 ID、原名、原帖链接、实际语境及归因、核查依据、风险类别、处理结果、未入选原因和已选代表证据关联。超额同类项、未命中项和客观不可访问项均有去处，不要求公开文档显示所有词、所有来源和内部档案。
- “停止追加终稿”不等于停止剩余调查；新的类别、实质风险变化和反证仍必须处理。终稿按风险类别给出凝练摘要、必要的风险点和额度内证据，不能把全部档案搬到附录规避精简。

## 交付与验收

调查交付的是分类合并后的风险类别、代表事实及文字档案。顶部摘要、举例标题与平台正文使用可对应的类别索引；同一事件的原记录和质询补充说明合并更新，不重复追加。

终审核对：补查清单每项有实际原帖处置、全部成立的风险类别有代表性落点、代表证据未超过额度、同类超额事实已文字归档、未命中和客观不可访问处置有依据、实质风险与反证未漏。名词未出现在终稿、已归档的同类原帖未逐条展示，不构成 FAIL；未补查、错误归类、整类漏报、空档案或无来源结项才是缺项。机器提交记录采用甲方质询的 v2 补查／分类合同，不再用逐词全文出现校验。

## 发现门禁的分类合并合同

旧发现记录的 `record_fact(s)` 可以通过显式 `consolidation` 记录关联到同类代表证据，不能直接删除旧事实或把查询改成未发现。`discovery_gate.audit_discovery_review` 的 `consolidation` 参数、CLI 状态的同名字段及业务终审的 `business_risk_review.consolidation` 使用以下合同；未提供时保持原逐条终稿校验。

- 顶层精确字段：`version:1`、`task_id`、`source_revision`、`discovery_sha256`、`reported_facts_sha256`、`policy`、`archive`、`context_archives`、`entries`。两个内容哈希分别绑定未经修改的完整 discovery 对象与当前终稿事实去重排序后的列表，均采用 UTF-8、`ensure_ascii=False, sort_keys=True, separators=(",",":")` 的 JSON SHA-256。`source_revision` 是调查来源版本；飞书版本仍由业务门禁另行精确绑定。
- `policy`、`archive` 和 `context_archives` 中每项均为实际 `{path,sha256}` 文件引用。业务门禁要求 `policy` 与本次实际风险表来源相同。分类 archive 保存 `facts`（`original_text,source_urls,category_ids,disposition,reason`）和 `categories`（`id,policy_category,selected_facts:[{text}]`）；每类 1—4 例，具体原帖独立性和跨平台额度仍由质询 v2 门禁核对。上下文档案保存原帖文字、语境、归因和逐名词核查结果，不能用空文件代替。
- `entries` 完整覆盖每个原 `record` 实体的每条事实，精确字段为 `entity_index,fact,source_refs,archive_index,disposition,categories,representative_facts,reason`。必须保留原实体全部来源，并指向档案里同一原事实及非空处置理由；不能以另一个人的同名词条代替。
- `selected`、`selected_partial`、`archive_same_category` 必须与档案类别一致，每个类别至少有一条该类别档案中已选且当前终稿实际存在的代表事实；神韵不能借 LGBTQ 代表事实结项。`no_policy_hit` 和 `objective_unavailable` 必须与档案处置一致、无虚构类别或代表证据。缺条、错类、无真实档案、过期哈希和 pending 均不放行。
- 此合同只改变终稿呈现映射。原始来源全量语义审阅、全部名词查询、真实子代理回执、反向核对，以及独立甲方完整名词表质询、必记项原帖补查和全部文字归档仍必须通过原门禁。
