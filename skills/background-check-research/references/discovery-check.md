# 逐条语义、特殊名词提取与子代理全量审核

本流程用于每次实际背调取得的全部范围内公开材料，包括只指定一个账号或平台的调查。逐条语义分析、全部特殊名词提取、一个专门子代理逐项查询审核、原始材料反向核对和发现门槛均为必需步骤。严格禁止跳过；发现跳步立即 FAIL，返回最早缺失步骤实际补做，禁止继续进入后续完成、终审或交付环节。原时间窗、平台及用户范围约束保持有效；不推断未公开的政治、宗教、性取向等个人属性。

## 逐条语义先于筛选

1. 获取各平台内容时保留完整原文和来源映射。所有平台内容取得后，核对当次全部批次；可以在获取过程中先行逐批分析，但最终逐条覆盖不得缺项。正文、配文、引用附言、本人回复、搜索结果以及纳入范围的图片文字／画面、视频语境都按原要求实际读取。
2. 对每条材料先分析完整语义，再提取全部有具体指称的特殊名词。每条保留一句语义分析、全部原文名词及批次／条目索引；没有特殊名词时写出该条的具体语义依据。不能先按风险词过滤再阅读，不能只读首尾摘要、标题、截断正文或命中片段，也不能用采集数量、遍历终点或自动摘要证明已分析。
3. 特殊名词包括人名、组织、作品／IP／角色所属作品、演出／巡演、活动、媒体、品牌、地名、口号、历史事件／典故、域名、标签中具体对象、缩写和外语别名等。熟悉或看似普通的对象也必须提取。平台导航、普通日期及不指向特定对象的常用词不按特殊名词收录；不能把陌生词笼统归入这些排除类。
4. 使用同一阅读缓存保存逐条语义记录和去重名词表，不复制整套正文或另建研究包。批次指纹只用于绑定实际源文件，不证明语义完成。所有取得条目的集合必须与语义分析条目集合逐项对应；新增或变动内容必须补读、重新提取和交回审核。

## 当次创建一个专门名词审核子代理

全部范围内材料已逐条分析并提取名词后，主代理必须在**本任务中**实际创建一个专门子代理。这是用户明确授权的必需调查步骤；不为每个平台或名词分别起代理，不创建无材料可做的等待代理。

- 给子代理任务 ID、范围、当前材料版本、完整去重名词表、每个名词的所有相关原文／来源、当前业务口径及本规程。使用最小上下文，不提供预设风险答案。真实创建调用和完成返回须可定位，不能由主代理冒填子代理 ID。
- 子代理对**全部名词逐条查询并审核**：实际对象、名称和别名、相关背景、主体在原文中的行为及业务口径。每个名词保留实际查询、所读来源和明确结论。不能按知名度、褒贬、是否命中风险词抽样；“我知道这个名字”不能替代本次查询。确认的同一对象别名可合并一次查询，必须记录别名依据；同名不同实体须分开。
- 每个名词一次有边界主查询，必要时一次备用。已完成有界查询仍未查清的，保留事实未知和查询依据，但核查执行已完成，不无限挂待办。已确认客观不可访问的按[访问结项规则](access-policy.md#客观不可访问项按无问题结项)记“无问题”结项。逐项名词查询不占用人物 1—3 组主动扩搜额度，也不能因额度耗尽而跳过；真实未执行查询与执行后未知必须区分，访问权限、同域名互斥和止损规则继续适用。
- 子代理逐项给出 `record`、`clear` 或 `pending`，以完整查询回执返回。不得把批评、讽刺、观看作品、实际参加、支持、成员身份或募资混为一谈。名称出现本身不自动证明支持或敏感个人属性。
- 主代理核对所有提取名词均有对应审核、所有查询有来源、真实子代理返回与回执一致。漏审一个名词、只有批量总评、空清单或未完成返回均立即 FAIL，交回这个子代理补齐，禁止主代理代签。反查发现的新名词通过 followup 交给同一子代理，不另起一组代理。

## 阅读时先识别对象

每批阅读原文、转发／引用、链接标题、配图文字和范围内的重点视频时，先问“这里在谈谁、什么作品或什么活动”。提取有内容意义的作品、角色所属作品、演出／巡演、组织、媒体、品牌、活动、口号、域名及关键公开人物名称；不以已知风险词表、知名度、褒贬语气或发布频率作提取门槛。平台导航、普通日期及没有对象意义的常用词可按类别排除，不逐项外查。

- 原文语义提取与名称、标签、域名等字面线索互补；大写词正则、关键词扫描、OCR 和模型提取均只产生候选，不能单独证明没有遗漏。
- 首轮按来源保留名字及一句必要上下文，归并大小写、简繁、当地语、译名和缩写。只有指向同一对象的来源支持才合并；同名不同实体分开。OCR 不清、短链去向未知、只看到截断标题时保留待查。
- 名称去重后由专门子代理逐项查询实际对象、公开活动／作品内容和相关争议，优先官方介绍、演职员表或活动页，再核实争议来源。已读上下文可作为依据交接，不能代替所有名词的本次查询；不得因熟悉名字就默认无风险，也不因词表没有该名就停止。
- 有意推广、参加、购买、募资、合作、参演、公开称赞，以及批评、讽刺、转述分别记录。**批评或玩笑不自动删除对象关联；出现对象名称也不自动证明支持、成员身份或实际参加。**记录和分级仍以已核实的行为及适用业务口径为准。
- 背景核对限于当前帖子所指对象及解释实际关系所必需的来源：作品／活动的主办、出品、赞助方及其性质可以跟进，不能用机械的一跳限制截断这条证据链；不递归调查其他参与者的私生活或全部社交关系。重复名称复用本任务已有依据；不同事件、时期或主体行为改变结论时才补查。具体线索沿既有主查询加一次备用的额度处理，仍不清楚就记录已执行和未坐实的终态，不无限等待；此类首轮核查不受“成品后最多三个补查子题”的限制。

## 平台结束前从原始材料查漏

由原执行者复用已读缓存和媒体接触图，换一个问题做一次有边界的复核：“哪些名称、链接、图片符号或疑点还没有解释？”先看来源，再比对去重对象结果；不要先读报告或风险清单后只找支持它们的例子。不从网页首页重爬，不为形式独立另开代理。

反向核对覆盖本次纳入的材料范围，按现有批次处理，不把整套缓存一次塞回上下文。它聚焦名称、关系与遗留疑点，不要求重复逐张放大已经看清的媒体。新名称补入同一清单并交回同一个名词审核子代理逐项查询，全部完成后再关闭。再按适用风险类别核对未处理线索；这不是为每类盲跑一组外部查询。

若用户指出漏项，撤回受影响的完成结论，补查同一漏检机制影响的材料，不能仅补用户点名的一条便恢复整体完成。

## v2 状态与实际依据

在现有 `current-state.json` 或等价任务状态中维护 `discovery_review` v2，同一份结果用于调查完成和交付审阅。逐条语义记录是新增的强制依据，不能以旧版“不记录普通帖子”的条款删掉。源批次复用原缓存，不复制正文或在成品增加过程章节。

`execution_review.applicable_steps` 根据原范围列齐当前阶段之前适用的全部步骤，至少包含下面的五个发现步骤；账号确认、平台搜索、媒体检查等也要列入，交付和画像补查进入对应阶段时追加。每步有真实依据；`skipped_steps` 是尚未补做的跳步，不为空即 FAIL，必须补做后才能清除。

`semantic_review.source_batches` 登记全部实际 JSON 批次的绝对路径、唯一批次 ID、条目数组键名和文件 SHA-256；脚本重新读取文件核对条目索引和指纹。非标准来源先在同一缓存中保留真实来源映射，不能只导出命中部分。每条分析有 `batch_id`、零起始 `item_index`、`status:"complete"`、语义 `summary` 和全部原文 `names`；单条无名词时写 `no_special_terms_reason`。整体未提取或空名词清单一律 FAIL 并退回复核；确实无法形成名词的输入如实说明，不编造名词凑数。

采集时同步生成原始批次清单（复用采集器现有 manifest），由 `acquisition_manifest:{path,sha256}` 引用，其 JSON 内容为 `{task_id,source_revision,source_batches:[{batch_id,path,items_key,sha256}]}`。逐条分析的批次集合必须与此采集清单完全相等，防止少申报整批材料；不能在审阅后按已分析子集反造采集清单。主代理核对采集真实返回与清单一致，脚本无法发现从未登记的来源。名词子代理回执另绑定 `acquisition_sha256`，对应本次采集清单的实际指纹。

以下是字段示意，必须以当次真实工作填写，不能直接用示意值验收：

```json
{
  "version": 2,
  "mode": "assistant_research",
  "task_id": "本次任务ID",
  "primary_agent_id": "实际主代理ID",
  "scope": "本次账号、平台及时间范围",
  "source_revision": "现有缓存批次终点或任务材料版本",
  "reviewed_revision": "实际完成反向核对的同一版本",
  "source_refs": ["现有缓存路径#实际纳入批次／媒体页"],
  "acquisition_manifest": {"path": "采集时生成的清单绝对路径", "sha256": "实际采集清单SHA-256"},
  "execution_review": {
    "status": "complete", "source_revision": "现有缓存批次终点或任务材料版本",
    "applicable_steps": ["source_collection", "semantic_analysis", "term_extraction", "term_subagent_review", "reverse_review"],
    "steps": [
      {"step_id": "source_collection", "status": "complete", "evidence_refs": ["真实采集返回"]},
      {"step_id": "semantic_analysis", "status": "complete", "evidence_refs": ["逐条分析定位"]},
      {"step_id": "term_extraction", "status": "complete", "evidence_refs": ["完整名词表定位"]},
      {"step_id": "term_subagent_review", "status": "complete", "evidence_refs": ["真实子代理返回"]},
      {"step_id": "reverse_review", "status": "complete", "evidence_refs": ["反向核对记录"]}

  },
  "semantic_review": {
    "status": "complete", "source_revision": "现有缓存批次终点或任务材料版本",
    "source_batches": [{"batch_id": "batch-1", "path": "实际源批次绝对路径", "items_key": "items", "sha256": "实际源文件SHA-256"}],
    "items": [{"batch_id": "batch-1", "item_index": 0, "status": "complete", "summary": "发布者以假设句吐槽演出广告反复出现", "names": ["Example Stage"]}]

    "name": "Example Stage",
    "aliases": [],
    "source_refs": ["原帖URL或现有缓存定位"],

    "relation": "主体吐槽广告；没有观演陈述",

```

`reverse_pass.names` 保存反向核对实际识别的去重名称，不能从 `entities` 自动复制来伪装复核；新名称必须有对应实体和子代理审核。实体 `disposition` 为 `record`、`clear` 或 `pending`，不能只以“普通内容”“未命中词表”排除。应记录的实体填 `record_fact`；同一实体多条事实可用 `record_facts`，不重复创建同名实体来绕过去重审核。没有分类合并记录时，门禁仍逐条核对终稿事实；按新规则精简终稿时，保留冻结的全量发现记录，并按[类别合并机器合同](risk-consolidation.md#发现门禁的分类合并合同)绑定完整分类档案与同类终稿代表事实，不修改历史核查结论来规避校验。

子代理回执是实际产出的 JSON：`version:2`、`task_id`、`agent_id`、`source_revision`、`status:"complete"`、`spawn_ref`、`result_ref` 与任务记录一致；`acquisition_sha256` 等于实际采集清单指纹。`reviews` 对每个去重实体恰有一条 `{name,status:"complete",queries:[{query,source_refs:[实际查阅来源]}],conclusion}`。主代理不能代写查询或结论；接收后可将真实完成返回定位绑定到 `result_ref` 元数据。有别名的实体另有 `alias_evidence:[{alias,source_refs:[别名依据]}]`；不得以别名合并隐藏未查名词。

`aliases` 是本次原文中已消歧的名称映射，不是全世界的别名词典。不同实体共用缩写时，按实际上下文决定每次所指；共有缩写事实在 `ambiguous_aliases` 或实体说明中保留来源，不能强行并成同一个实体，也不能删掉共有关系来过门槛。同一原词在不同条目确实指向不同实体时，提取名称加明确的上下文消歧标签并保留原词／原帖定位，子代理分别查询对应实体。

`open_items` 只保留尚有应执行动作的正文、媒体、名称或范围问题及下一步。已确认客观不可访问项记“无问题”，移入终态记录；有界查询完成仍未知的名称保留未知结论，不把它当成漏查。实体可用 `terminal_outcome:{status:"complete",kind:"objective_unavailable",conclusion:"无问题",reason:"实际客观原因",evidence_refs:["实际访问依据"]}` 记录终态；有界查询后仍未知时 `kind:"bounded_inconclusive"`、`conclusion:"未坐实"`。后者允许保留 `disposition:"pending"` 表示事实未知，前者使用 `clear`；均须有真实子代理已完成查询回执，不能用字段代替工作。原始不可见内容不计入已阅读内容数。`source_revision` 使用已有材料版本，源批次指纹由工具计算；新增或变更材料后更新版本，旧的 `reviewed_revision` 和子代理回执不能直接沿用。v1 assistant 记录必须补执行缺失步骤，不得自动补字段升级。

用户只要求同步其人工结论或修订旧文档而没有授权新调查时，使用 `mode="user_supplied"` 或 `mode="existing_report_only"`，保留 `scope`、用户原话 `instruction` 和该指令的 `source_ref`；这表示本次不评定调查发现能力，不得据文档 PASS 宣称完成新背调。实际由助手执行的调查不能改填这两个模式绕过检查；旧记录缺字段也不是豁免理由。

## 完成检查

本发现门槛通过只表示调查发现记录达到要求，不是最终提交许可。全部适用调查与原有终审后，还必须调用独立 Skill [甲方质询](../../client-challenge-background-check/SKILL.md)，另建首轮只接收名词表的甲方子代理；不得复用本文件中的名词查询子代理。其完整名词表质询、曾警惕及最终疑问名词的全量原帖补查与文字归档、六项事实答复及固定拒绝规则均由该独立 Skill 维护；终稿按[类别合并规则](risk-consolidation.md)选代表证据，不要求所有名词出现。

平台或整项范围完成前运行：

```powershell
python "$env:BACKCHECK_SKILLS_ROOT/background-check-research/scripts/discovery_gate.py" --state <当前任务状态JSON>
```

脚本读取实际批次和子代理回执，核对逐条覆盖、提取是否缺失／为空、是否漏审名词、别名依据、当次一个独立子代理、版本、跳步和最终事实。它**不联网、不识别未知实体，也不能证明语义零遗漏或认证代理调用真伪**；终审必须对照真实创建／返回消息，不能只接受自填 ID 或 PASS。对话交付提供 `reported_facts`；飞书共享业务门禁把 `record_fact` 与 `confirmed_hits` 比对。

**没有提取名词、任何名词未全部审阅、逐条语义缺项、跳过适用步骤、缺子代理依据或过期记录均立即 FAIL。** 按返回的 `repair_stage` 补做最早缺失规则，再重新审阅，禁止继续进入下游完成阶段。应记事实漏报同样 FAIL。真实源文件／回执访问故障可返回 BLOCKED，但不能把缺记录、漏查或空表伪装成访问故障。工具失败不自动改变 Goal 状态；用户明确范围变更按原话处理。

## 修改方法后的验证

保留本次已知失误作回归样本，但它不能充当盲测。行为测试给执行者新规则、现实形态的原始材料和可查来源，不给预期答案或目标名称；预期结果单独保存，测试结束后再比对。至少覆盖：普通语气中的陌生名称、外语别名、同名不同对象、批评／反讽、作品与演员归因、纯图片线索和来源不足。合成材料须明确标为离线测试，不能作为真实人物结论。

分别报告已知样本回归、脚本约束测试、答案隔离行为测试及真实新任务的结果。未做的项目如实写未做，不用格式校验成功声称发现能力已修复。普通背调由主代理逐条分析和提取，并创建一个专门名词审核子代理；除此之外保持项目代理数量限制。隔离行为测试按技能验证授权执行，不充当真实人物调查结论。
