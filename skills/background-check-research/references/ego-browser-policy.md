# 背调调查部分统一使用 ego 浏览器

用户于 2026-10-31 明确要求：所有背调中需要联网或在社媒完成的内容，必须在 ego 浏览器中完成；必要时由执行者自行授权、新建工作区，无需再次请求用户授权。用户随后明确：本规则只覆盖普通背调、特殊背调、专项调查及续查的调查部分。飞书交付、API 回读和终审继续使用原有飞书 OpenAPI／MCP 流程，不受本条调查入口限制。

## 入口与授权

- 先读取当前 `ego-browser` 技能并运行 `ego-browser skill`，读到结束标记，按安装版本的接口操作。首次使用直接执行真实任务操作，失败后再诊断安装或连接。
- 可以自行创建、授权或领取本任务所需的 ego TaskSpace；这是用户已给出的持续授权，不再询问能否新建、是否允许浏览或是否可以进入本任务工作区。记录实际返回的 `spaceId`，后续优先复用。
- 通常一个背调批次使用一个 TaskSpace；确有任务隔离或重建需要时可自行创建新空间，保存原断点和原因。不得以新空间重置重试额度、绕过访问限制、安全拒绝或用户接管，也不得认领、操作无关的用户工作区。创建成功不等于网页已读。
- 必须由用户本人完成的密码、验证码、二次验证或设备确认，按实际页面和工具能力处理；没有观察到这些阻碍时，不把超时、技术报错或工作区创建当成“等待用户授权”。这不扩大到代用户发帖、关注、私信、付费或新增第三方账号权限。

## 调查联网步骤都留在 ego 内

- 调查中的搜索引擎检索、社媒主页和回复、原帖及媒体、网页来源核验、调查资料下载，均通过 ego TaskSpace 内的页面完成。飞书模板读取、成品写入、API 回读和终审仍按交付及审阅技能执行。
- 不使用 `web.run`、外置搜索/抓取工具、Edge broker、`web-access/scripts/cdp-session.ps1`、CUA、其他浏览器、shell/Node/Python 网络请求或独立 API/MCP 客户端执行这些调查联网步骤。ego 的 Node 运行器用于控制浏览器和本地文件，不用 Node `fetch` 绕开浏览器。
- 批量读取优先使用 ego 的页面快照、可见 DOM `page.evaluate()` 和网页原生导出/下载。必要且已获授权的公开请求只能使用 ego 文档支持的页面内 `page.fetch()`，遵守页面权限与 CORS；不提取认证材料、不调用未授权私有接口。ego 自带 `page.cdp()` 属于该浏览器内部接口，不等同于外部 Edge CDP broker。
- 其他技能或参考中保留的 Edge、外置搜索、API/MCP 和旧采集脚本示例，只是非当前通道的历史接口资料，不授权在调查部分运行；飞书 API/MCP 交付和审阅规则不变。业务格式、来源归因、阅读范围和验证标准仍有效。

## 本地处理与故障

- 用户提供的原始包、通过 ego 合法取得的导出、已读材料，可继续使用本地脚本解包、去重、拼联系表、分析和校验。无需把离线文件重新上传浏览器，也不能把缓存或拼图生成当作已审阅。
- 沿用同一实际故障的断点和恢复计数，正常尝试一次、有限恢复一次；控制故障累计三分钟没有进展就保留缺口并推进独立工作。需要外部搜索作为替代来源时，也在 ego 内打开搜索引擎。
- 需要用户专属验证时只挂起对应步骤。技术失败不自动暂停整个任务，也不偷偷回退旧入口。实际材料仍可读、可分析时继续处理。
- 当前页面的内容、归属及媒体实际可见才计完成。调查中的读取或媒体缺口如实保留，不把浏览器连通、下载完成或换工作区当作已审阅。
